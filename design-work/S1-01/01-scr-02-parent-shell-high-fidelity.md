# SCR-02 — شاشة الأب الرئيسية / Parent Shell

- **الحالة:** High-Fidelity design specification — بانتظار اعتماد مالك المنتج
- **المقاس المرجعي:** 360 × 800 dp بالضبط
- **الاتجاه:** RTL
- **الفرع:** `feat/governance-v2`
- **النطاق:** SCR-02 فقط
- **المرجع البنيوي:** `design-work/S1-01/00-design-foundation-and-audit.md` — قسم SCR-02
- **المراجع الوظيفية:** S1-01 SPEC §9-1 و§9-2 / REQ-001, REQ-004, REQ-008, REQ-012
- **المراجع التصميمية:** color-tokens.md, typography.md, navigation-patterns.md, spacing-and-grid.md, components.md, states-empty-loading-error.md

> هذا ملف تصميم للشاشة المطلوبة فقط. لا يغيّر المواصفة أو نظام التصميم أو سجل القرارات، ولا ينشئ قراراً عاماً جديداً.

## 1. قواعد بصرية ثابتة لهذه الشاشة

| الخاصية | القيمة الملزمة |
|---|---|
| Frame | 360 × 800 dp — إعادة تكوين مخصصة، وليس تصغير تخطيط أكبر |
| خلفية الصفحة | Cream `#FCFAED` |
| البطل الرئيسي الوحيد | Navy `#1F3A6B` |
| الحالة الآمنة فقط | Green `#1F6B3B` |
| التنبيه المتوسط فقط | Orange `#CF5B2C` |
| الطوارئ / SOS فقط | `#D92D20` |
| الذهبي | `#C8A24A` للجوائز والزخرفة الصغيرة فقط؛ لا يظهر في هذه الشاشة، ولا يستخدم كنص على خلفية فاتحة |
| درجات 50–950 | لا تُخترع أو تُشتق داخل هذا التصميم؛ أي درجة غير منصوص عليها تبقى TBD |
| التحذير العنبري | TBD؛ لا تستخدم قيمة Hex أو تخمّنها |
| الخط | IBM Plex Sans Arabic |
| الأرقام | غربية فقط: 0–9، مع tabular numerals للقيم الزمنية |
| أحجام النص | لا يقل أي نص عن 12sp؛ نص الجسم لا يقل عن 14sp |
| هوامش المحتوى | 16dp يميناً ويساراً |
| شبكة القياس | مضاعفات 4dp |
| البطاقات | أبيض `#FFFFFF`، حد 1dp `#F0F0F0`، radius 20dp، elevation 0 |
| الأفاتار | دائرة كحلية `#1F3A6B` وبداخلها حرف «أ» أبيض؛ بلا صورة |
| اسم العائلة | «عائلة الحداد» |
| العلامة الكلمية | «عائلتي» نصاً فقط؛ لا رمز شعار أو رسم مبتكر |
| SOS | دائرة عائمة `#D92D20`، النص اللاتيني `SOS` فقط، أسفل اليمين، ظاهرة دائماً |

### ملاحظة اتساق مرجعية — لا تُخفَ

قيمة SOS المحددة في توجيه مالك المنتج لهذه الشاشة هي `#D92D20`، بينما جدول `color-tokens.md` الحالي يسجل `red.500 = #B42318`. يعتمد هذا التصميم قيمة المالك `#D92D20` لزر SOS في SCR-02 فقط، ولا يغيّر رمز اللون العام أو يزعم أن ملف نظام التصميم قد عُدّل. يلزم إبقاء الفرق ظاهراً عند أي مراجعة لاحقة لتوحيد المرجع؛ لا تُجرِ هذا التوحيد ضمن هذه المهمة.

## 2. التكوين عالي الدقة — 360 × 800

### 2.1 هيكل الشاشة

- المساحة العلوية والسفلية للنظام ضمن إطار 360 × 800؛ يحترم المحتوى SafeArea.
- AppBar واحد يحمل العلامة النصية «عائلتي» ومؤشر الاتصال.
- شريط الحالة السياقية يظهر فقط عند وجود حالة فعلية تستدعيه (مثل عدم الاتصال أو تحديث إلزامي). لا توجد شارة اتصال افتراضية مزخرفة.
- بطل كحلي واحد مهيمن يحمل ملخص العائلة وقراءاتها الأساسية.
- أسفل البطل تظهر أسطح الأنظمة المسجلة والمسموحة للمستخدم فقط؛ لا تُنشأ بطاقات أو وحدات افتراضية.
- شريط التنقل السفلي مشتق من `nav_eligibility` والمنح الفعلية؛ لا يظهر مسار غير متاح.
- زر SOS طبقة عائمة مستقلة فوق المحتوى والتنقل.

### 2.2 مخطط التوزيع

```text
┌────────────────────────────────────┐ 360
│ SafeArea / System status           │
├────────────────────────────────────┤
│ عائلتي                     اتصال   │ AppBar
├────────────────────────────────────┤
│ [بانر سياقي — عند الحاجة فقط]      │
├────────────────────────────────────┤
│                                    │
│  ┌──────────────────────────────┐  │
│  │       البطل الكحلي الوحيد     │  │
│  │                              │  │
│  │  عائلة الحداد       (أفاتار)  │  │
│  │  حالة العائلة                │  │
│  │  آخر مزامنة                  │  │
│  └──────────────────────────────┘  │
│                                    │
│  [أسطح الأنظمة المسجلة والمصرح بها]│
│  [بطاقات بيضاء مسطحة فقط]         │
│                                    │
├────────────────────────────────────┤
│ الرئيسية | العائلة | المحادثات | ...│
│                              SOS   │
├────────────────────────────────────┤
│ System navigation / SafeArea      │
└────────────────────────────────────┘
800
```

المخطط يوضح ترتيب الطبقات فقط؛ الأبعاد النهائية لكل منطقة تتبع قياسات 4dp، ولا يسمح بتمرير أفقي أو تداخل SOS مع أهداف التنقل.

### 2.3 الرأس (AppBar)

- الارتفاع: 56dp ضمن SafeArea.
- بداية RTL: العلامة النصية «عائلتي» بخط IBM Plex Sans Arabic، وزن 600، حجم 20sp، بلون كحلي.
- الطرف المقابل: مؤشر اتصال صغير مع تسمية نصية عند الحاجة؛ يعرض الحالة الحقيقية فقط.
- لا صورة شعار، ولا جرس، ولا بحث، ولا تحية، ولا شارات إضافية.
- لا يُعرض «عائلة الحداد» في الرأس؛ يظهر داخل البطل فقط لتجنب التكرار.

### 2.4 البطل الكحلي المهيمن

- سطح واحد فقط بخلفية `#1F3A6B`، دون تدرج أو ظل أو زخرفة.
- العرض: 328dp (360 − 16 − 16).
- نصف القطر: 20dp.
- الحشوة الداخلية: 16dp.
- الترتيب من اليمين إلى اليسار:
  1. اسم العائلة «عائلة الحداد» — أبيض، 20sp، وزن 600.
  2. الأفاتار: دائرة 48 × 48dp، كحلية، حرف «أ» أبيض 20sp؛ لا صورة ولا أحرف أخرى.
  3. تسمية «حالة العائلة» وقيمتها الفعلية إن توفرت من مصدر الحالة.
  4. تسمية «آخر مزامنة» والقيمة الزمنية الفعلية من آخر مزامنة ناجحة، بأرقام 0–9.
- لا تعرض حالة «آمنة» إلا إذا أكد مصدر النظام الحالة الآمنة فعلاً؛ عندها فقط تستخدم الأخضر `#1F6B3B` مع نص صريح. لا تستنتج الأمان من الاتصال أو نجاح المزامنة.
- لا تخترع قيمة آخر مزامنة أو عدداً أو نسبة أو مؤشراً صحياً. عند غياب القيمة، استخدم حالة البيانات المحددة في §4 بدلاً من قيمة تجريبية.

### 2.5 أسطح الأنظمة

- تظهر فقط وحدات `nav_eligibility` المسجلة والمسموحة وفق المنح الفعلية للمستخدم.
- كل سطح ظاهر بطاقة بيضاء مسطحة: حد 1dp `#F0F0F0`، radius 20dp، elevation 0.
- لا تضف عنوان قسم أو وصفاً أو أيقونة أو شارة أو عداداً ما لم يكن جزءاً من تعريف الوحدة المسجلة ومطلوباً منها.
- لا تُعرض وحدة غير مفعلة أو غير مفوضة كعنصر معطل في هذه الشاشة؛ تُخفى من التنقل والأسطح الرئيسية وفق مرجع التنقل.
- لا تُنشأ بيانات أو محتويات تجريبية لملء الفراغ.

### 2.6 التنقل السفلي

- Compact فقط في هذا الإطار: Bottom Navigation.
- العناصر للمالك `adult + is_owner=true` هي بالترتيب المعتمد: «الرئيسية»، «العائلة»، «المحادثات»، «التحكم»، «المزيد»؛ لا تتجاوز خمسة.
- لا تُعرض هذه القائمة حرفياً للبالغ غير المالك؛ عناصره تُشتق من منح الصلاحيات الفعلية حسب navigation-patterns.md.
- النص 12sp كحد أدنى، والأهداف التفاعلية 48 × 48dp على الأقل، والفاصل 8dp على الأقل.
- حالة العنصر النشط لا تعتمد على اللون وحده؛ تستخدم تمييزاً شكلياً ونصياً.
- زر SOS لا يُعد عنصراً سادساً في التنقل؛ هو طبقة طوارئ مستقلة.

### 2.7 زر SOS الدائم

- دائرة 56 × 56dp، مثبتة أسفل اليمين فوق طبقات الشاشة، مع احترام SafeArea.
- اللون `#D92D20`، والنص الوحيد داخل الزر `SOS` باللاتينية، واضح ومقروء.
- هدف لمس لا يقل عن 48dp، ولا يتداخل مع شريط التنقل أو محتواه.
- الضغط المطول 3 ثوانٍ كما في REQ-007؛ لا يُفعّل SOS بلمسة عابرة.
- لا نص عربي داخل الزر، ولا أيقونة أو عداد أو شارة إضافية.
- يجب أن يبقى ظاهراً في كل حالات الشاشة الأربع.

## 3. سلوك العرض والتفاعل

- تُعرض بيانات الكاش المحلي فوراً ثم تُحدّث؛ لا ينتظر الغلاف استجابة الشبكة كي يرسم هيكله.
- أي قيمة تعرض تاريخ/وقت مزامنة تشير إلى آخر مزامنة ناجحة فعلاً، لا وقت آخر محاولة.
- فشل قسم أو وحدة واحدة لا يعطل بقية الشاشة.
- إذا كان المستخدم بالغاً غير المالك، تُشتق الوحدات والتنقل من المنح الفعلية؛ لا يُستنتج حق التحكم من صفة البالغ وحدها.
- لا يوجد تبديل إلى وضع الطفل أو تبديل ملف مستخدم من هذا الغلاف.
- لا تظهر إجراءات غير مطلوبة أو عناصر زخرفية أو شارات تسويقية.

## 4. مصفوفة الحالات المطلوبة

### 4.1 نجاح (Success)

- يظهر البطل الكحلي واسم العائلة والأفاتار.
- تعرض حالة العائلة ووقت آخر مزامنة من بيانات حقيقية.
- تعرض الأسطح المسجلة والمصرح بها فقط.
- الأخضر `#1F6B3B` لا يظهر إلا إذا كانت حالة آمنة مؤكدة.
- SOS حاضر دائماً.

### 4.2 تحميل (Loading)

- يظهر الهيكل من الكاش أولاً.
- عند غياب بيانات الكاش، يحافظ البطل على أبعاده ويستخدم Skeleton داخل مواضع القيم فقط؛ لا تستخدم شاشة دوّار فارغة.
- لا تختفِ العلامة النصية أو اسم العائلة المعروف أو زر SOS.
- لا تستخدم أرقاماً أو قيماً وهمية كبيانات مؤقتة.

### 4.3 فارغة (Empty)

- حالة أول استخدام للعائلة: يظهر البطل بهوية العائلة الثابتة، وتظهر قائمة الإعداد المعتمدة فقط إذا كانت عناصرها معرفة من مركز القيادة/الإعداد الأولي.
- لا تنشئ بطاقات وحدات وهمية أو نصوصاً تسويقية أو هدفاً زمنياً.
- إذا لم توجد وحدات مسجلة/مسموحة، لا تملأ المساحة ببطاقات فارغة؛ تبقى المساحة نظيفة.
- SOS والتنقل المسموح يظلان ظاهرين.

### 4.4 خطأ (Error)

- إذا فشل تحميل وحدة واحدة: تعرض الوحدة المتأثرة حالة خطأ داخل سطحها فقط مع إجراء إعادة المحاولة؛ بقية الشاشة تظل عاملة.
- إذا فشل الاتصال: يظهر بانر الحالة السياقية المعتمد، وتُعرض بيانات الكاش مع بيان أنها محفوظة/قديمة بصدق.
- إذا لم توجد بيانات كاش: لا تخترع حالة عائلة أو وقت مزامنة؛ تعرض مواضع القيم حالتها الفارغة/غير المتاحة بنص واضح.
- لا تعرض كوداً تقنياً للمستخدم.
- لا تستخدم الأحمر إلا للطوارئ/SOS في هذا التصميم؛ لا تلوّن أخطاء الأقسام بالأحمر. استخدم نمط الخطأ النصي والمكوّن المعتمد دون اختراع لون حالة.
- SOS يظل متاحاً.

## 5. قائمة تحقق القبول

- [ ] Frame مضبوط على 360 × 800dp بالضبط، مع SafeArea.
- [ ] التخطيط إعادة تكوين للهاتف؛ لا تمديد أو تصغير لتصميم أكبر.
- [ ] خلفية كل الصفحة `#FCFAED`.
- [ ] يوجد بطل كحلي مهيمن واحد فقط بلون `#1F3A6B`.
- [ ] اسم العائلة هو «عائلة الحداد» دون اختلاف.
- [ ] العلامة الكلمية «عائلتي» نص فقط.
- [ ] الأفاتار دائرة كحلية بحرف «أ» أبيض، بلا صور.
- [ ] البطاقات بيضاء، حد 1dp `#F0F0F0`، radius 20dp، elevation 0.
- [ ] الهوامش الأفقية 16dp وكل المسافات على شبكة 4dp.
- [ ] IBM Plex Sans Arabic مستخدم في جميع النصوص.
- [ ] لا يوجد نص أصغر من 12sp ولا نص جسم أصغر من 14sp.
- [ ] جميع الأرقام المعروضة غربية 0–9 ولا تختلط بأنظمة أرقام أخرى.
- [ ] لا يوجد نص ذهبي على خلفية فاتحة؛ لا يستخدم الذهبي في هذه الشاشة.
- [ ] الأخضر للحالة الآمنة المؤكدة فقط.
- [ ] البرتقالي للتنبيه المتوسط فقط؛ لا يستخدم كزخرفة أو لون نجاح.
- [ ] لا تُستخدم درجة Amber أو أي درجة 50–950 غير محددة في توجيه المالك.
- [ ] زر SOS دائري، `#D92D20`، وداخله `SOS` لاتينية فقط، أسفل اليمين، حاضر في كل الحالات.
- [ ] لا يتداخل SOS مع التنقل ولا يقل هدف لمسه عن 48dp.
- [ ] عناصر التنقل والأسطح مشتقة من السجل والمنح الفعلية، وبحد أقصى خمسة عناصر رئيسية.
- [ ] حالات النجاح والتحميل والفارغة والخطأ موثقة دون بيانات وهمية.
- [ ] لا توجد شارات أو أسطر أو عناصر غير مطلوبة.
- [ ] لم تُعدّل ملفات الحوكمة أو المواصفة أو نظام التصميم أو main أو التطبيق أو قاعدة البيانات.

## 6. حدود الاعتماد

هذه مواصفة تصميم عالية الدقة لـ SCR-02 وليست اعتماداً نهائياً ولا تنفيذاً برمجياً. تبقى قيمة SOS المذكورة أعلاه تعارضاً موثقاً مع قيمة red.500 في ملف الألوان الحالي، ولا يُجرى تعديل عالمي لها ضمن هذه المهمة.

**نقطة التوقف:** لا يبدأ SCR-03 ولا أي شاشة أخرى حتى يراجع مالك المنتج SCR-02 ويعتمده صراحةً.
