# كتالوج شبكة اتصال تيليجرام ومراكز البيانات (Telegram MTProto & Datacenter Catalog)

> **طبيعة الاتصال في Telegram:** لا تعتمد تيليجرام على واجهات REST API التقليدية (HTTP JSON)، بل تستخدم بروتوكولاً ثنائياً فائق السرعة والأمان يُدعى **MTProto v2.0** يعمل عبر قنوات TCP/UDP المباشرة، مع وجود قناة بديلة عبر **WebSockets (TLS)** للمتصفحات والشبكات المقيدة.

---

## 1. خريطة مراكز البيانات العالمية (Telegram Datacenters - DCs)

توزع تيليجرام خوادمها على 5 مراكز بيانات رئيسية حول العالم لتقليل زمن الاستجابة (Latency) لكل منطقة جغرافية:

| معرف المركز (DC ID) | الموقع الجغرافي | بروتوكول TCP المباشر (IPv4) | قناة الويب البديلة (Secure WebSocket) |
| :---: | :--- | :--- | :--- |
| **DC 1** | ميامي، الولايات المتحدة الأمريكية | `149.154.175.50:443` | `wss://vesta.web.telegram.org/apiws` |
| **DC 2** | أمستردام، هولندا (أوروبا والشرق الأوسط) | `149.154.167.51:443` | `wss://venus.web.telegram.org/apiws` |
| **DC 3** | ميامي، الولايات المتحدة الأمريكية | `149.154.175.100:443` | `wss://aurora.web.telegram.org/apiws` |
| **DC 4** | أمستردام، هولندا (الملفات والوسائط الضخمة) | `149.154.167.91:443` | `wss://flora.web.telegram.org/apiws` |
| **DC 5** | سنغافورة (آسيا والمحيط الهادئ) | `91.108.56.165:443` | `wss://pluto.web.telegram.org/apiws` |

## 2. بنية إطار حزمة بروتوكول MTProto v2.0 (Packet Framing)

كل حزمة تمر بين تطبيق الهاتف وخوادم تيليجرام تتبع التنسيق الثنائي التالي:

```
+-------------------+--------------------+------------------------------------------+
| auth_key_id (8B)  |   msg_key (16B)    |        encrypted_data (Variable)         |
+-------------------+--------------------+------------------------------------------+
                                         | salt (8B) | session_id (8B) | msg_id(8B) |
                                         | seq_no(4B)| msg_length (4B) | payload... |
                                         +------------------------------------------+
```

### شرح الحقول:
1. **`auth_key_id` (8 بايت):** المعرف الفريد للمفتاح السري المشترك للمستخدم.
2. **`msg_key` (16 بايت):** جزء من الهاش المشتق من البيانات غير المشفرة والمفتاح السري (يُستخدم لمنع العبث بالبيانات والتحقق قبل فك التشفير).
3. **`encrypted_data` (مشفرة بـ AES-256-IGE):**
   - **`salt` (8 بايت):** ملح تشفيري متغير كل 30 دقيقة لحماية الجلسة.
   - **`session_id` (8 بايت):** معرف اتصال الجلسة الحالية.
   - **`msg_id` (8 بايت):** طابع زمني دقيق جداً (Timestamp نانوي) فريد لكل رسالة يمنع هجمات إعادة الإرسال (Replay Attacks).
   - **`seq_no` (4 بايت):** عداد تسلسلي للرسائل؛ ترقيم فردي للرسائل التي تتطلب تأكيد استلام (ACK)، وترقيم زوجي للرسائل العادية.
   - **`payload`:** كائن الدالة أو الرسالة بتنسيق Type Language (TL).

---

## 3. رسائل تأكيد الاستلام اللحظية (Acks & Transport State)

- **`msgs_ack` (Constructor: `0x62d6b459`):** يرسل الخادم أو العميل مصفوفة من أرقام `msg_id` لتأكيد وصول الرسائل دون الحاجة لإعادة طلبها.
- **`bad_server_salt` (Constructor: `0xed483874`):** إشعار بتحديث الملح التشفيري عند مرور أكثر من نصف ساعة.
- **`http_wait` (Constructor: `0x9299359f`):** تقنية Long-Polling لإبقاء القناة مفتوحة حتى وصول رسائل جديدة.
