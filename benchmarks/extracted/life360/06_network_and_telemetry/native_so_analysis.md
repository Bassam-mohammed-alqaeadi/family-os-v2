## 2. تحليل عميق لمكتبة `librealm-jni.so` (The High-Throughput Core)

### 2.1. لماذا اختار Life360 محرك Realm C++ بدلاً من الاكتفاء بـ SQLite التقليدي؟
1. **انعدام تكلفة التحويل (Zero-Copy Architecture):**  
   في SQLite العادية، عندما تقرأ تطبيقاً بيانات من قاعدة البيانات، يقوم نظام أندرويد بنسخ البايتات من القرص إلى ذاكرة النظام، ثم تحويلها إلى كائنات Java/Kotlin عبر `Cursor`. هذه العملية تستهلك وقتاً وذاكرة مكلفة عند استقبال 100 عينة في الثانية من الحساسات. محرك Realm يرسم ملف الذاكرة مباشرة (`mmap()`)، وتصل فئات C++ مباشرة إلى البايتات دون وسيط.
2. **عزل خيوط المعالجة المتزامنة (Thread Confinement):**  
   يسمح Realm لخيط معالجة حساسات التسارع بكتابة القراءات دون أي حظر لخيط واجهة المستخدم (Zero UI Jitter).

## 3. تحليل آليات التقاط الانهيارات الأصلية (`libcrashlytics*.so`)

- تسجل المكتبة معالجات إشارات مخصصة (Custom Signal Handlers) عبر استدعاءات `sigaction()` لاعتراض الإشارات القاتلة:
  - `SIGSEGV` (11): محاولة قراءة أو كتابة عنوان ذاكرة غير صالح (Invalid Memory Access).
  - `SIGABRT` (6): استدعاء قسري لإيقاف العملية عبر دالة `abort()`.
  - `SIGBUS` (7): خطأ في محاذاة الذاكرة الفيزيائية.
  - `SIGFPE` (8): أخطاء الفاصلة العائمة الحسابية مثل القسمة على صفر.
- عند التقاط الإشارة، تتولى مكتبة `libcrashlytics-trampoline.so` تفريغ محتويات سجلات المعالج (`PC`, `LR`, `SP`, `CPSR`) ومسار مكدس الاستدعاءات (Stack Unwinding) وحفظها في ملف مصغر مشفر داخل مجلد التطبيق الخاص، لرفعه تلقائياً فور إعادة تشغيل التطبيق.
