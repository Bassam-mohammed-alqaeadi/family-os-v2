# استراتيجية التخزين المؤقت للبيانات دون اتصال (Offline Telemetry Buffering Strategy)

> **الهدف الهندسي:** تفكيك المعمارية الهجينة التي يعتمدها Life360 في جمع آلاف نقاط الموقع، قراءات حساسات الـ 100Hz، وأحداث البلوتوث محلياً أثناء انقطاع الإنترنت أو القيادة في الأنفاق والمناطق النائية، وضغطها ورفعها تلقائياً عند استعادة الاتصال.

---

## 1. المعمارية الهجينة المزدوجة (Dual-Engine Storage: Realm + Room)

كما كشف فحص المكتبات الأصلية (`librealm-jni.so`)، يجمع Life360 بين محركين للتخزين:
1. **محرك Realm Mobile C++ Engine (Ring Buffer عالي السرعة):**  
   - مخصص لتلقي قراءات الحساسات السريعة (High-Frequency IMU 100Hz) وعينات الـ GPS اللحظية.
   - يتميز Realm بانعدام تكلفة التحويل (Zero-Copy Architecture) ومعدل كتابة فائق يتجاوز 10,000 سجل في الثانية دون إبطاء خيط المعالجة الرئيسي (UI Thread).
2. **محرك AndroidX Room / SQLite (التخزين العلائقي المستمر):**  
   - مخصص للجداول الهيكلية: بيانات الدوائر، الأماكن المحمية، ملخص الرحلات المكتملة، وإعدادات المستخدم.

```mermaid
flowchart LR
    GPS["GPS / IMU 100Hz / Tile BLE"] --> RealmBuffer["Realm C++ Memory Ring Buffer<br/>(تخزين فوري عالي السرعة)"]
    RealmBuffer --> SyncWorker["TelemetrySyncWorker<br/>(كل 60 ثانية أو عند توفر Wi-Fi)"]
    SyncWorker --> Compress["ضغط الحزم (Gzip / Protobuf)"]
    Compress --> Endpoints["نقطة النهاية السحابية:<br/>POST /v4/driving/logs/upload<br/>POST /v1/ingest"]
    Endpoints --> Ack{"هل تم استلام الرد بنجاح (200 OK)؟"}
    Ack -->|نعم| Purge["حذف العينات القديمة من Realm"]
    Ack -->|لا (أوفلاين)| Retain["الاحتفاظ بها وتأجيل الرفع (Exponential Backoff)"]
```

## 2. آليات تقليص حجم البيانات وضغط الحزم (Data Compression & Decimation)

لتقليص استهلاك باقة الإنترنت للمستخدم وسعة التخزين:
1. **فلترة النقاط الزائدة أثناء التوقف (Dwell Suppression):**  
   عندما يتوقف المستخدم في مكان محدد لأكثر من 3 دقائق، يتم إيقاف تسجيل الإحداثيات المكررة، ويكتفي المحرك بتسجيل "حدث استقرار" (`Dwell Event`) واحد يحمل الإحداثية وزمن البدء وزمن الانتهاء.
2. **ضغط المسارات عبر خوارزمية Ramer-Douglas-Peucker (RDP):**  
   يتم تبسيط خط سير الرحلة المكون من 3000 نقطة إلى حوالي 200 نقطة جوهرية فقط تحافظ على شكل المنعطفات والطرق بدقة \( \pm 5 \) أمتار، مما يقلص حجم حمولة الـ JSON بنسبة تزيد عن 85%.
3. **تغليف الحزم بترميز Gzip:**  
   يتم إرسال حزم التلمتري برأس اتصال `Content-Encoding: gzip`، مما يضغط مصفوفات الأرقام والإحداثيات بدرجة ضغط عالية جداً قبل مغادرة الجهاز.

## 3. استراتيجية إعادة المحاولة الذكية (Exponential Backoff & Network Transitions)

- في حال فشل الاتصال بالسيرفر، لا يقوم التطبيق بتكرار الطلبات بصورة عشوائية لمنع استنزاف البطارية، بل يطبق خوارزمية تراجع أسي مع تشويش عشوائي (Exponential Backoff with Full Jitter):
  \[
  T_{\text{wait}} = \min(T_{\text{max}}, T_{\text{base}} \times 2^{\text{attempt}}) \pm \text{RandomJitter}
  \]
- **مستقبل حالة الشبكة (`NetworkCallback`):**  
  يسجل التطبيق مستمعاً رسمياً لدى نظام التشغيل عبر `ConnectivityManager.NetworkCallback`. فور تحول حالة الهاتف من `Disconnected` إلى `Connected` (خاصة عبر Wi-Fi)، يستيقظ `TelemetrySyncWorker` فورياً لتفريغ كافة السجلات المعلقة دون انتظار المجدول الزمني.
