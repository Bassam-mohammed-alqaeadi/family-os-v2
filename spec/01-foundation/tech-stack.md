# المكدس التقني (Tech Stack)

> الحالة: معتمد للتنفيذ | القرارات: D-003, D-004, D-005, D-007, D-009 | يكمله: architecture.md
> **قاعدة الإصدارات:** تُثبَّت الإصدارات عند بدء التنفيذ على آخر إصدار مستقر/LTS، وتُسجَّل في `repo` عبر ملفات القفل (lockfiles). لا إصدار مكتوب هنا لأنه يتقادم؛ المكتوب هو **الاختيار والسبب**.

## 1. الخادم
| الطبقة | الاختيار | السبب |
|---|---|---|
| وقت التشغيل | Node.js (LTS) | قرار D-005، منظومة واسعة |
| اللغة | TypeScript (strict) | أمان الأنواع، وفهم الوكيل للشيفرة |
| الإطار | NestJS مع محوّل Fastify | نظام وحدات مدمج يطابق المعمارية، حقن اعتماديات، أداء جيد |
| التحقق | Zod (مخططات مشتركة) | مصدر واحد للتحقق والأنواع |
| ORM/الاستعلام | Drizzle ORM + ترحيلات SQL خام | تحكم كامل بـ SQL وRLS والمخططات المتعددة |
| قاعدة البيانات | PostgreSQL | مصدر الحقيقة، RLS، JSONB، التقسيم |
| الذاكرة/الطوابير | Redis + BullMQ | ذاكرة مؤقتة، pub/sub، مهام |
| اللحظي | Socket.IO مع Redis adapter | إعادة اتصال، غرف، توسع |
| توثيق الواجهات | OpenAPI (مولَّد من المخططات) | يولّد عميل Dart تلقائيًا ويقلل الأخطاء |
| الجدولة | BullMQ repeatable jobs | موحّد مع الطوابير |
| الاختبار | Vitest + Testcontainers (Postgres/Redis حقيقيان) + Supertest | اختبارات تكامل واقعية |
| الجودة | ESLint, Prettier, dependency-cruiser | يفرض حدود الوحدات |

## 3. التشفير والأمان
- **التشفير الطرفي (لاحقًا):** بروتوكول معتمد وليس ابتكارًا ذاتيًا (على نمط Signal، عبر مكتبة موثوقة). لا يُبنى تشفير مخصص أبدًا.
- **كلمات المرور:** لا كلمات مرور (D-007). OTP + رموز جلسة.
- **الأسرار:** مدير أسرار المزوّد، وفي التطوير ملفات `.env` غير مرفوعة.
- **فحص التبعيات:** فحص آلي للثغرات (Dependabot/ما يعادله) + فحص أسرار مسرّبة في CI.

## 4. الخدمات الخارجية (مجردة خلف واجهات داخلية)
كل مزوّد خلف **منفذ (Port)** داخلي، فيمكن تبديله دون المساس بالوحدات:
| القدرة | الواجهة | ملاحظة |
|---|---|---|
| إرسال OTP/SMS | `SmsPort` | مزوّدان على الأقل (أساسي واحتياطي)، واختيارهما مرتبط بالدول (O-001) |
| الإشعارات | `PushPort` | FCM/APNs |
| الخرائط والأماكن | `MapsPort` | مفتوح |
| الدفع والاشتراكات | `BillingPort` | متاجر التطبيقات + مزوّد ويب لاحقًا |
| الذكاء الاصطناعي | `AiPort` (D-009) | تبديل النموذج دون مساس بالمنطق |
| التخزين الكائني | `StoragePort` | متوافق مع S3 |

## 5. الاستضافة والبنية (موجز، التفاصيل في environments-and-devops)
- **حاويات (Docker)** لكل شيء، ونشر محايد للمزوّد.
- **قاعدة PostgreSQL مُدارة** بنسخ احتياطي وPITR، وRedis مُدار.
- اختيار المزوّد ومنطقة البيانات **معلّق بـ O-001** (متطلبات إقامة البيانات والخصوصية تختلف بين الدول). يُوصى بالبدء بمزوّد سحابي كبير واحد مع منطقة قريبة من الدول المستهدفة.
- بناء iOS عبر خدمة سحابية (D-004): يُنفَّذ بخدمة CI مخصصة لـ Flutter (مثل Codemagic) مع توقيع وشهادات مُدارة، بديلها macOS runners في CI العامة.

## 6. التكامل والتسليم المستمر (CI/CD)
- **المستودع:** GitHub-class مع فروع قصيرة العمر، وطلبات دمج إلزامية بمراجعة آلية.
- **خطوط CI:** تحليل ساكن، اختبارات وحدة، اختبارات تكامل (حاويات)، فحص حدود الوحدات، فحص مخطط التحكمات والصلاحيات (control/permission schema tests)، فحص الأمان، بناء الحاويات.
- **تطبيق:** بناء أندرويد (AAB) وiOS (IPA) في خطوط منفصلة، توزيع داخلي للتجريب (Firebase App Distribution/TestFlight).
- **ترحيلات قاعدة البيانات:** تُطبَّق آليًا في النشر بخطوة منفصلة قابلة للإيقاف، وتتبع نمط التوسيع ثم الانكماش (expand/contract) لتفادي التعطل.

## 7. معايير اختيار أي أداة جديدة (للوكيل والفريق)
1. مفتوحة المصدر أو لها بديل واضح (لا احتجاز بمزوّد).
2. صيانة نشطة وإصدارات حديثة.
3. أمان وترخيص مناسبان للاستخدام التجاري.
4. أثر على حجم التطبيق والبطارية (للعميل).
5. تُوثَّق في ADR صغير (سبب الاختيار والبدائل) قبل الاعتماد.

## 8. ما يُمنع
- مكتبات غير مصانة أو بلا إصدارات حديثة لمهام الأمان أو التشفير.
- بناء تشفير أو مصادقة خاصة.
- ربط الشيفرة مباشرة بمزوّد خارجي دون Port.
- تخزين أسرار أو بيانات شخصية في السجلات.
- أي اعتماد على وكيل أو نموذج محدد داخل الشيفرة (D-009).

## 9. المسائل المفتوحة في هذا الملف
- **T-001:** مزوّد الخرائط (يُحسم في S1-07).
- **T-002:** مزوّد SMS/OTP وبدائله لكل دولة (يتأثر بـ O-001).
- **T-003:** مزوّد الاستضافة ومنطقة البيانات (يتأثر بـ O-001، يقابل D-022 المقترح).

## 10. معايير القبول
1. مستودع جديد يبني ويختبر الخادم والتطبيق بأمر واحد لكل منهما.
2. كل خدمة خارجية خلف Port، وبدائلها وهمية (fakes) في الاختبار.
3. عميل Dart يُولَّد من OpenAPI دون تعديل يدوي.
4. خط CI يفشل عند ترحيل غير آمن أو تغيير في مخطط التحكمات دون تحديث السجل.
5. بناء iOS ينتج ملف IPA قابلًا للتجريب من خط سحابي دون جهاز Mac محلي.
