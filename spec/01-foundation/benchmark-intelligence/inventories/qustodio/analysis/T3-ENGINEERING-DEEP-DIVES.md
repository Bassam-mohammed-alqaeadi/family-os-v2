## 1. المسار الهندسي الأول (Track A): معمارية الإنفاذ والحماية ومكافحة التلاعب

### 1.1 معضلة Device Admin مقابل Device Owner
- أثبت الفحص الشامل لـ `AndroidManifest.xml` أن تطبيق الوالدين **لا يُعلن أي مستقبِل لـ Device Admin أو Device Owner**.
- محرك الحماية يعتمد على الثنائية المعمارية المنفصلة (Two-App Ecosystem Topology):
  - **تطبيق الوالدين (PASA):** وحدة تحكم قائمة بذاتها، مسؤولة عن إرسال السياسات واستعراض الأحداث.
  - **تطبيق الطفل (Companion):** الوكيل المثبت على جهاز الطفل؛ وهو الذي يطلب إذن `BIND_DEVICE_ADMIN` لتفعيل قفل الشاشة ومنع إلغاء التثبيت غير المصرح به.

### 1.2 بنية التوقيع وحماية الطلبات الأصلية عبر `libsigner.so`
- وثّق ملف `NativeLibHelper.java` (#L1-L27) تحميل المكتبة الأصلية `System.loadLibrary('signer')` وإعلان الدوال الأصلية:
  - `nOnResume(Context context)`
  - `nSign(String requestPayload, byte[] authSecret)`
- **الدور المعماري:** توليد توقيع رقمي مشفر (HMAC Request Attestation) لحماية طلبات التتبع والإحالة في Adjust SDK من التزييف أو التعديل أثناء النقل (Man-In-The-Middle Prevention).

### 1.3 بوابة المصادقة الحيوية وحماية جلسة الوالد (`BiometricActivity`)
- فحص كود `BiometricActivity.java` (#L1-L150):
  - إنشاء `BiometricPrompt.PromptInfo.Builder` مع تفعيل خاصية `setAllowedAuthenticators(BIOMETRIC_STRONG | DEVICE_CREDENTIAL)`.
  - اعتراض الرجوع من الخلفية وإجبار المستخدم على البصمة قبل عرض بيانات الأطفال أو فك القفل اللحظي.

### 1.4 التحليل المرحلي الصارم لأمر القفل الفوري (Instant Lock 6-Stage Evidence Lifecycle Trace)
لضبط حدود الإثبات ومنع ادعاء انضباط جهاز الطفل لمجرد ضغط الوالد على زر الواجهة، تم تفكيك مسار القفل الفوري (`QU-FUN-000023` / `QU-RES-000007`) إلى 6 مراحل متعاقبة:

| المرحلة | الوصف التقني والعملياتي | مستوى الإثبات | الحالة الدليلية والحدود المعمارية |
|---|---|:---:|---|
| **1. Command Requested** | نقر الوالد على زر "Lock Device Now" في واجهة `QuickActionsContainer.tsx` وإطلاق Redux Action | **Level A** | **مثبت قطعياً بالكود (Proven):** رصد معالج الحدث والـ Action في كود TypeScript المستعاد. |
| **2. Server Accepted** | توجيه Redux Epic واستدعاء نقطة النهاية `qapi.device.lock(childId, deviceId)` المصرحة في `qapi.ts` (#L620) | **Level A** | **مثبت قطعياً بالكود (Proven):** رصد الاستدعاء وتجهيز المعايير وترويسات المصادقة. |
| **3. Command Dispatched** | استلام الخادم السحابي للأمر وتوجيه رسالة FCM Push عالية الأولوية لأجهزة الأطفال المسجلة | **Level B** | **نموذج مشتق (Inferred):** يُستدل عليه معمارياً من بنية النظام، ولا يمكن فحصه مباشرة لغياب كود الخادم. |
| **4. Command Delivered** | وصول رسالة الـ Push إلى جهاز الطفل عبر خوادم Google FCM وشبكة الجهاز | **Level C** | **غير مثبت (Unverified / Unavailable):** يتطلب سجلات شبكة الطفل أو فحص جهاز الطفل الحي. |
| **5. Command Applied** | تفعيل وكيل الرقابة في تطبيق الطفل (Accessibility / Device Admin) لطبقة القفل وحجب التفاعل | **Level C** | **غير مثبت (Unverified / Unavailable):** محجوب داخل حزمة تطبيق الطفل (Qustodio Kids Companion APK) غير المتاحة. |
| **6. Command Verified** | إرسال جهاز الطفل إشعار تأكيد التنفيذ للخادم السحابي وتحديث حالة البطاقة لدى الوالد | **Level C** | **غير مثبت (Unverified / Unavailable):** لا يمكن إثبات حلقة التأكيد المرتدة إلا بوجود كود الطرفين. |

> **قاعدة الحوكمة الملزمة:** لا يجوز ادعاء أن جهاز الطفل قد قُفل لمجرد أن تطبيق الوالد أرسل طلب HTTP أو حدّث واجهته محلياً بنجاح.

## 2. المسار الهندسي الثاني (Track B): فلترة الويب وتصنيف الشبكة والواجهات البرمجية

### 2.1 معمارية الفلترة المزدوجة (Dual-Mode Inspection Architecture)
*ملاحظة إثبات هامة حول فلترة الويب:* فحص حزم الشبكة واعتراض استعلامات DNS عبر `VpnService` هي نماذج معمارية مشتقة (Level B) تخص **تطبيق الطفل (Qustodio Kids Companion)**. أما تطبيق الوالدين (PASA) المفحوص فيقتصر دوره على تكوين السياسات الـ 29 واستعراض خلاصة المواقع المزارة.
1. **الاعتراض عبر VpnService المحلي:**
   - اعتراض حزم الشبكة وتوجيه استعلامات DNS (Port 53) إلى خادم DNS محلي يعمل داخل جهاز الطفل.
   - فحص استعلامات UDP/TCP ومقارنة أسماء النطاقات (Domain Names) بالقائمة المحفوظة محلياً أو بالخدمة السحابية.
2. **فحص حزم TLS المبدئية (SNI Inspection):**
   - قراءة حقل Server Name Indication في مصافحة TLS Client Hello للتعرف على الموقع المشفر دون الحاجة لكسر تشفير HTTPS أو تثبيت شهادة جذر مخصصة (CA Certificate).

### 2.2 المطابقة الشاملة لكتالوج الواجهات البرمجية (REST API Reconciliation)
- تم فحص ملف `qapi.ts` (#L1-L1633) وتفكيك هيكليته:
  - **96 مجموعة نقاط نهاية وظيفية.**
  - **130 إعلان استدعاء HTTP صريح.**
  - **99 نقطة نهاية فريدة لـ URL.**
  - **435 موقع استدعاء مباشر في كود TypeScript.**
- **النطاقات السحابية الخمسة:**
  1. `api.qustodio.com`: الواجهة الأساسية (الملفات، الحصص، الروتينات، الإحصائيات).
  2. `auth.qustodio.com`: إدارة الجلسات، التوكنات، و2FA.
  3. `family.qustodio.com`: خرائط الموقع والأماكن المحمية.
  4. `ff.qustodio.com`: رايات الميزات (Feature Flags).
  5. `api.pro.qustodio.net`: واجهات Linewize المدرسية للطلاب.

## 3. المسار الهندسي الثالث (Track C): إدارة وقت الشاشة والحصص وقواعد البيانات

### 3.1 قيد الـ 1440 دقيقة ومعمارية الحصص اليومية
- في `timeRules/timeQuota.ts` (#L1-L77):
  - الحصة اليومية محصورة رياضياً في المجال المغلق:
    $$	ext{Quota} \in [0, 1440] \quad (	ext{دقائق اليـوم الكاملة})$$
  - القيمة `1440` تمثل "وقت غير محدود" (Full Quota)، بينما `0` تمثل "حظر كامل" (Day Without Quota).
  - يتم تخزين الحصة كمصفوفة تعيين أسبوعية لسبعة أيام تبدأ من الأحد.

### 3.2 خوارزمية التقويم الدائري والالتفاف الليلي (Sunday-to-Monday Rollover Theorem)
- في `RulesWizard/routines.ts` (#L1-L242):
  - عندما يبدأ الروتين في المساء وينتهي صباح اليوم التالي (مثال: من 21:00 إلى 07:00)، فإن شرط الانتهاء الرياضي يلتف عبر منتصف الليل:
    $$	ext{Period}_1 = [	ext{Start}, 1440) \quad (	ext{في اليوم } D)$$
    $$	ext{Period}_2 = [0, 	ext{End}] \quad (	ext{في اليوم } (D+1) \pmod 7)$$
  - تدعم الخوارزمية الالتفاف الدائري من يوم الأحد (اليوم 6) إلى يوم الاثنين (اليوم 0) دون حدوث تضارب حسابي أو فقدان لحالة القفل الليلي.

### 3.3 محرك بطاقة الحالة الحية الموحدة للطفل (Unified Now Card Decision Engine)
- في `unifiedNowCard/unifiedNowCard.ts` (#L1-L349):
  - يفحص 26 شرطاً منطقياً لتقييم حالة الطفل الآن:
    1. هل الجهاز مقفل يدوياً عبر الوالد؟ (`PAUSED_BY_PARENT`)
    2. هل هو ضمن فترة روتين نوم نشطة؟ (`IN_SLEEP_ROUTINE`)
    3. هل هو ضمن فترة روتين دراسة نشطة؟ (`IN_STUDY_ROUTINE`)
    4. هل هو ضمن ساعات الدوام المدرسي لـ Linewize؟ (`IN_SCHOOL_PERIOD`)
    5. هل استنفذ حصته اليومية المقررة؟ (`TIME_EXHAUSTED`)
    6. الاستخدام متاح وطبيعي (`FREE_TIME`)
  - يتم تحديث البطاقة تفاعلياً مع كل تغيير في الوقت أو الحالة.

### 3.4 تشريح قاعدة بيانات SQLite المحلية (22 جدولاً)
- تم حسم جداول `local_db_schema.sql` الـ 22 أصولاً:
  1. **15 جدولاً لـ Firebase Cloud Firestore v16:** إدارة كاش المستندات والتعديلات دون اتصال.
  2. **6 جداول لـ Google DataTransport v7:** جدولة التيليمتري وسجلات الأخطاء في الخلفية.
  3. **جدول واحد لـ Cordova NativeStorage (`native_storage_kv`):** حفظ الـ 26 مفتاحاً الدائمة لتسلسل Redux والرموز الحساسة.
  4. **حالة الجداول التجارية المعتمدة:** "No Qustodio-owned relational business tables were identified in the examined SQL schema."
   - يثبت الفحص الشامل أن تطبيق Qustodio PASA لا يُنشئ أي جدول علائقي خاص به في SQLite، بل يعتمد على حفظ شجرة حالة Redux كاملة بصيغة نصية متسلسلة (Serialized JSON) تحت مفتاح `state` داخل جدول `native_storage_kv` (التابع لإضافة كوردوفا)، بالتكامل مع كاش وثائق Firestore للمستندات غير المتزامنة وبيانات الخادم السحابي البعيد.
