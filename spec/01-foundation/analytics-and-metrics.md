# التحليلات والمقاييس (Analytics & Metrics)

> الحالة: معتمد للتنفيذ | القرارات: D-018, D-023, D-024 | يعتمد على: data-governance.md §9, legal-and-compliance.md, monetization-and-plans.md
> **القيد الحاكم:** منتج عائلي بخصوصية صارمة للأطفال: تحليلات مستعارة ومجمّعة، بلا محتوى ولا موقع دقيق ولا معرّفات إعلانية.

## 1. المبادئ
1. **قياس ما يهم قراراتنا** لا كل شيء.
2. **الخصوصية بالتصميم:** مخطط الأحداث يرفض P0 (data-governance §9).
3. **تجارب مسؤولة:** لا على السلامة ولا على الأطفال دون موافقة (monetization §9).
4. **مقاييس صادقة:** تعريف مكتوب وشيفرة واحدة لكل مقياس (Metrics Layer).
5. **الفريق كله يرى نفس الأرقام** (مصدر حقيقة واحد).

## 2. إطار المقاييس
### 2.1 نجم الشمال (North Star)
**العائلات النشطة أسبوعيًا بتفاعل متعدد الأفراد (WAF-M):** عدد العائلات التي فيها ≥ 2 أفراد نشطين أسبوعيًا ولديها استخدام فعلي لخدمة واحدة على الأقل.
- السبب: قيمة المنتج في العائلة لا الفرد، والفرد المنفرد لا يحقق وعد «نظام التشغيل العائلي».

### 2.2 مؤشرات (AARRR مكيّفة للعائلة)
| المرحلة | المقاييس |
|---|---|
| **الاكتساب** | تثبيتات، تسجيلات، تكلفة اكتساب لكل عائلة مفعّلة، مصدر القناة (خصوصي) |
| **التفعيل** | إتمام إنشاء العائلة، **إضافة أول فرد خلال 24 ساعة**، اقتران أول جهاز طفل، أول رسالة، أول مشاركة موقع، وقت الوصول للقيمة (TTV) |
| **الاحتفاظ** | D1/D7/D30 للعائلة والفرد، احتفاظ الجهاز المقترن، تعطّل الحماية (فقد صلاحيات) |
| **الإيراد** | تحويل مجاني→مدفوع، ARPPU، الإلغاء، الاحتفاظ بالاشتراك (§6) |
| **الإحالة** | دعوات مُرسلة/مقبولة، معامل الانتشار العائلي |

### 2.3 مقاييس السلامة والثقة (ذات أولوية مساوية للنمو)
- زمن تسليم SOS (p50/p95) ونسبة النجاح.
- نسبة الأجهزة ذات الحماية الكاملة مقابل `unavailable_on_device`.
- معدل تنبيهات المخاطر وتقييم الأهل لدقتها (مفيدة/غير مفيدة).
- معدل التراجع عن إعدادات (دليل ارتباك)، وطلبات الموافقة وزمن البت.
- شكاوى الخصوصية، وطلبات الحقوق ضمن SLA.

### 2.4 مقاييس الجودة التقنية
أخطاء الجلسات (crash-free)، زمن بدء التطبيق، زمن حسم الإعدادات، نجاح المزامنة، زمن الإشعار (من الحدث للجهاز)، نجاح OTP لكل دولة/مزوّد، تكلفة SMS لكل مستخدم.

### 2.5 مقاييس الذكاء الاصطناعي
استخدام لكل ميزة، تكلفة لكل عائلة، رضا (👍/👎)، معدل الرفض/الإبلاغ، وقت الاستجابة، نسبة الحصة المستهلكة.

## 3. تصنيف الأحداث والمخطط
### 3.1 العقد
```
AnalyticsEvent {
  name,               // domain.object.action  مثال: chat.message.sent
  version, ts_client, ts_server,
  pseudo_user_id, pseudo_family_id,   // مستعارة، تُدوَّر عند الحذف
  experience_profile, plan_tier, country, app_version, platform,
  props{}              // حقول مسموحة بالمخطط فقط، لا نصوص حرة
}
```
- **الحقول الممنوعة:** محتوى الرسائل، أسماء، هواتف، موقع دقيق (يُقرَّب لمنطقة واسعة إن لزم)، معرّفات إعلانية، نص مدخل الطفل.
- **سجل الأحداث (Event Registry)** في المستودع: كل حدث له مالك، غرض، `data_class`، احتفاظ. CI يفشل إن أُرسل حدث غير مسجّل أو بحقول خارج المخطط.
- **عند غياب الموافقة/في دول تمنع:** تعطيل أحداث التحليلات الاختيارية أو تقليلها إلى مقاييس تشغيل ضرورية فقط (من `CountryLegalProfile`).

### 3.2 المسار التقني
العميل → مجمّع أحداث على الجهاز (دفعات) → نقطة استقبال خاصة بنا → التحقق من المخطط → تقطير (مستعار) → مستودع تحليلات منفصل → طبقة مقاييس → لوحات.
- **لا SDK تحليلات خارجية تجمع معرّفات الجهاز أو الإعلان** (D-024). ولو استُخدم مزوّد، فبنقطة وسيطة تخلص الحقول وتحت عقد DPA.
- تسليم مرة على الأقل مع إزالة تكرار بالمعرّف.
- اختيار المستودع مفتوح (G-004).

## 4. طبقة المقاييس (Metrics Layer)
- كل مقياس معرّف في ملف (`metrics/*.yaml`): الاسم، الصيغة، الأحداث المصدر، الفلاتر، نافذة الزمن، المالك، التفسير.
- مثال:
```
metric: waf_m
definition: count_distinct(pseudo_family_id)
  where week_active_members >= 2 and any(service_event) in week
owner: product
```
- التغييرات مراجَعة (PR)، وتاريخ التعريفات محفوظ.

## 5. اللوحات
| اللوحة | الجمهور |
|---|---|
| تنفيذية (نجم الشمال، إيراد، احتفاظ) | القيادة |
| النمو والتفعيل (قمع الانضمام لكل دولة/قناة) | المنتج والنمو |
| السلامة والثقة | المنتج والامتثال |
| الصحة التقنية | الهندسة |
| الذكاء والتكلفة | الهندسة والمالية |
| الإيراد والاشتراكات | المالية والمنتج |
- لا لوحة تعرض شريحة أقل من العتبة k (data-governance §9.2).

## 6. مقاييس الإيراد
MRR/ARR، ARPPU، التحويل لمدفوع، الاحتفاظ بالاشتراك، Churn الطوعي مقابل الفشل في الدفع، LTV/CAC، تكلفة الخدمة (SMS، ذكاء، تخزين) لكل عائلة، هامش إجمالي لكل خطة. مصدر الحقيقة المالية هو نظام الفوترة، والتحليلات للتتبع.

## 7. التجارب (Experimentation)
- **التنفيذ:** أعلام وقيم L1 مع **تعيين مستقر لكل عائلة** (hash على `pseudo_family_id`) لا لكل فرد، حتى لا ترى العائلة تجارب مختلفة.
- **القواعد:**
  1. فرضية ومقياس نجاح ومقياس حماية (Guardrail) مسبقًا.
  2. حجم عينة وطول مدة محسوب قبل البدء، ولا توقف مبكر بناءً على النتائج.
  3. ممنوع التجريب على: السلامة (SOS، التنبيهات الحرجة)، واجهات الأطفال، عمليات الموافقة والخصوصية.
  4. تجارب الأسعار تمر بمراجعة قانونية ومنتج.
  5. سجل التجارب العلني داخليًا وأرشفة النتائج.
- **مقاييس الحماية الافتراضية:** crash-free، زمن الاستجابة، شكاوى، SOS، الاحتفاظ.

## 8. الإسناد والاكتساب بخصوصية
- بلا معرّفات إعلانية. الإسناد عبر أدوات المتاجر المحافظة على الخصوصية (Play Install Referrer، آليات إسناد Apple المجمّعة) وروابط الدعوة العائلية.
- تقارير القنوات مجمّعة. لا تتبع عبر التطبيقات.

## 9. الجودة والموثوقية للبيانات
- مراقبة حجم الأحداث لكل نوع، وتنبيه عند الانقطاع أو الارتفاع غير الطبيعي.
- اختبارات عقد (contract tests) بين العميل والمخطط، وتوثيق لكل إصدار تطبيق.
- مطابقة دورية بين الأرقام التشغيلية (قاعدة التشغيل) والتحليلية للمقاييس الحيوية (مثل عدد العائلات)، وتفسير الفروق.

## 10. الحوكمة
- مالك لكل حدث ومقياس، ومراجعة ربع سنوية لقائمة الأحداث (حذف ما لا يُستخدم).
- DPIA لأي قياس جديد يمس الأطفال.
- الاحتفاظ بالخام 13 شهرًا (`ret.analytics_raw`)، ثم تجميع.

## 11. معايير القبول
1. حدث غير مسجّل أو بحقل غير مسموح يُرفض في الاختبار وفي نقطة الاستقبال.
2. لا تصل للمستودع أي بيانات من الفئة P0 (اختبار مخطط شامل).
3. حذف عائلة يدوّر/يلغي `pseudo_family_id` ويُزيل أحداثها خلال المهلة المحددة.
4. WAF-M يُحسب بتعريف واحد في طبقة المقاييس ويطابق عينة يدوية.
5. تعيين التجارب مستقر للعائلة نفسها عبر أجهزتها، ولا تجربة على الميزات المحظورة.
6. دولة تمنع التحليلات الاختيارية تُنتج حدثًا تشغيليًا ضروريًا فقط (اختبار بحسب `CountryLegalProfile`).
7. لا شريحة أقل من k في أي لوحة.
8. لوحة الصحة تُظهر زمن تسليم SOS ونسبة الأجهزة ذات الحماية الكاملة بدقة، ويصدر تنبيه عند التدهور.
