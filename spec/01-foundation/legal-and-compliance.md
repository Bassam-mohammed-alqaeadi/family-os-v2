# الإطار القانوني والامتثال (Legal & Compliance)

> الحالة: معتمد للتنفيذ كإطار هندسي | القرارات: D-013, D-018, D-022, D-023, O-001 | يعتمد على: security-and-privacy.md
> **تنبيه جوهري:** هذا الملف يحدد **كيف تُبنى المنصة لتتحمل التعدد القانوني**، ولا يُغني عن مراجعة محامٍ مرخّص في كل دولة إطلاق. أي رقم قانوني (أعمار، مهل، عتبات) يُعامل **قيمة قابلة للضبط** في مصفوفة الدول (§3) وتُعتمد من مستشار قانوني قبل الإطلاق في تلك الدولة.

## 1. المبادئ
1. **الامتثال بالتصميم:** كل متطلب قانوني يتحول إلى تحكم أو سياسة أو اختبار قابل للفحص، لا إلى وثيقة منسية.
2. **القانون قيمة في الإعدادات (L1) لا في الشيفرة:** تغيير حكم قانوني في دولة لا يتطلب إصدارًا جديدًا (control-and-settings-architecture §4.1).
3. **الحدود الدنيا الأربعة (D-023)** هي الأرضية في كل دولة، والقانون المحلي قد يرفع السقف فقط.
4. **الإطلاق بحسب الجاهزية القانونية:** لا تُفعَّل دولة قبل اكتمال حزمتها (§3.3).
5. **الشفافية مع المستخدم** بلغة مبسطة وبنسخ موثقة (Versioned).

## 2. دور المنصة القانوني
| السياق | الدور المقترح | الأثر |
|---|---|---|
| بيانات المستخدمين (حسابات، محادثات، مواقع) | **مراقب بيانات (Controller)** | مسؤولية الأساس القانوني والإشعارات والحقوق |
| معالجة نيابة عن مؤسسة (مدارس/شركات) مستقبلًا | **معالج (Processor)** | عقد DPA، تعليمات المؤسسة |
| مزوّدو الخدمة (SMS، سحابة، ذكاء) | **معالجون فرعيون (Subprocessors)** | عقود DPA، سجل علني |
- **الوالد/الأب** يقرر ضمن العائلة (استعمال شخصي/منزلي)، والمنصة تظل مسؤولة عن تصميم حماية الأطفال وحدودها الدنيا.
- يُراجع الدور مع المستشار القانوني لكل ولاية قضائية.

## 3. استراتيجية الدول

### 3.1 مبدأ التوسع
- **مستوى A (إطلاق):** دول O-001، حزمة قانونية كاملة ومترجمة وخدمة دعم محلية.
- **مستوى B (لاحقًا):** دول تُفعَّل بعد استكمال المصفوفة.
- **مستوى C (محجوب):** لا إطلاق (عقوبات، قيود قانونية، مخاطر).

### 3.2 نموذج `CountryLegalProfile` (يغذي طبقة L1)
```
CountryLegalProfile {
  country_code, tier: A|B|C, status: draft|reviewed|active,
  digital_consent_age,              // سن الموافقة الرقمية المستقلة
  age_of_majority,                  // سن الرشد
  parental_consent_methods[],       // طرق التحقق المقبولة
  minimum_account_age?,             // إن وُجد
  data_residency: none|preferred|required,  home_region,
  cross_border_mechanism[],         // SCCs, adequacy, consent...
  dsr_response_days, breach_notice_hours, breach_authority,
  dpo_required, local_representative_required,
  special_category_rules{},         // دين، صحة، موقع الأطفال
  content_rules{},                  // محتوى محظور/إلزامي
  monitoring_rules{},               // قيود رقابة الأطفال والبالغين
  payment_rules{}, tax_rules{},
  legal_docs{ terms_version, privacy_version, child_notice_version },
  reviewed_by, reviewed_at, next_review_at
}
```
- يُخزَّن ويُدار كسجل داخلي (لا في شيفرة)، وكل تغيير يمر بموافقة قانونية ويُدقَّق.
- **القيم الافتراضية للحماية:** عند غياب ملف دولة: يُطبَّق الأشد (أعلى سن موافقة، أقصر احتفاظ، أقوى موافقة).

### 3.3 حزمة إطلاق دولة (Go-Live Checklist)
1. ملف `CountryLegalProfile` بحالة `active` بعد مراجعة قانونية محلية.
2. وثائق (الشروط، الخصوصية، إشعار الوالد) مترجمة ومراجعة قانونيًا.
3. آلية موافقة والدية معتمدة للدولة.
4. قرار الإقامة والنقل (§8) وتنفيذه.
5. تفعيل مزوّد OTP محلي واختبار الوصول.
6. متطلبات المتاجر للدولة، وتسعير وضرائب محلية.
7. DPIA مكتمل، ومسؤول/ممثل محلي إن لزم.
8. تدريب الدعم وجهة اتصال قانونية.

## 4. الوثائق القانونية (جرد)
| الوثيقة | الجمهور | ملاحظات |
|---|---|---|
| شروط الخدمة (ToS) | كل المستخدمين | نسخ لكل دولة/لغة |
| سياسة الخصوصية | كل المستخدمين | بالتزام D-023، تسرد المعالجات وأغراضها ومزوديها |
| **إشعار الوالد (Parental Notice)** | الوالد قبل إنشاء حساب طفل | ما يُجمع عن الطفل، الأغراض، الحقوق، كيفية الموافقة والسحب |
| **إشعار الطفل/المراهق المبسط** | الطفل/المراهق | لغة بحسب العمر (يغذي صفحة «ماذا تراقب عائلتي؟») |
| سياسة الاستخدام المقبول | الجميع | إساءة، محتوى، تتبع قسري |
| سياسة ملفات الارتباط/التتبع (الويب إن وُجد) | زوار الويب | |
| اتفاقية معالجة بيانات (DPA) | العملاء المؤسسيون/المزودون | |
| سجل المعالجين الفرعيين | علني | تحديث مع إشعار مسبق |
| سياسة الاحتفاظ والحذف | علنية ملخصة | تتوافق مع data-governance |
| سياسة المحتوى الديني والتعليمي (حقوق النشر) | داخلي/علني | §13 |
- **التقنية:** كل وثيقة نسخة مُرقَّمة، والموافقة تسجَّل مقابل رقم النسخة (ConsentRecord)، وتغيير جوهري يستدعي إشعارًا وإعادة موافقة.

## 5. الأساس القانوني للمعالجة
لكل معالجة (`processing_key`) أساس قانوني مسجّل:
| الأساس | أمثلة |
|---|---|
| تنفيذ العقد | الحساب، المحادثات، المزامنة |
| **الموافقة** | معالجة المحتوى للرقابة، سجل الموقع التفصيلي، الذكاء للأطفال، المحتوى الديني المخصص |
| المصلحة المشروعة (مع موازنة موثقة) | أمن المنصة، منع الاحتيال والإساءة |
| الالتزام القانوني | الاحتفاظ بسجلات، الاستجابة لأوامر مختصة |
| حماية المصالح الحيوية | SOS في حالات الخطر |
- جدول `processing_registry` في المستودع: المفتاح، الغرض، الأساس، الفئات P0-P4، الاحتفاظ، المزوّدون، ويُفحص CI بوجود سجل لكل معالجة جديدة.

## 6. الأطفال والموافقة الوالدية
- **القاعدة العامة:** موافقة والدية موثقة قبل أي جمع لبيانات طفل (حد دنيا 1).
- سن الموافقة الرقمية وطرق التحقق من `CountryLegalProfile`.
- **مراحل العمر في المنصة** (role-experience-model) مستقلة عن سن الموافقة القانوني، ويُدار الربط بينهما في L1.
- **مبادئ ثابتة:** تقليل البيانات، عدم الإعلان للأطفال، عدم التنميط التسويقي، عدم شروط تجبر الطفل على كشف أكثر مما يلزم، وتصميم لا يستغل الإدمان (لا dark patterns).
- **مفتاح الطفل:** الطفل لا يملك تعديل الموافقات، ويملك حق الشفافية.
- **سحب الموافقة:** الوالد يسحبها في أي وقت، فتتوقف المعالجة المعنية وتُحذف بياناتها بحسب السياسة.
- **التحول للبلوغ:** مسار الموافقة الذاتية عند بلوغ الابن (security-and-privacy §8.5).

## 7. الفئات الخاصة
| الفئة | الحساسية | الإجراء |
|---|---|---|
| **بيانات الدين** (محتوى ديني مخصص، تفضيلات) | فئة خاصة في كثير من الأنظمة | موافقة صريحة مستقلة، لا تنبؤ بالدين من السلوك، تعطيل افتراضي حيث يلزم |
| **الموقع الدقيق** (خاصة للأطفال) | عالية | موافقة، احتفاظ قصير، إفصاح ظاهر |
| **الصحة** (D-013، مستقبلًا) | فئة خاصة | لا تُفعَّل قبل مراجعة قانونية مستقلة (HIPAA/GDPR Art. 9 وما يعادلها)، وربما معمارية عزل |
| **البيانات الحيوية** | عالية | لا تُجمع على الخوادم: بيومتري الجهاز يعالجه نظام التشغيل فقط |
| **وثائق الهوية** (خزنة الوثائق مستقبلًا) | عالية | مراجعة مستقلة قبل التفعيل |
- لا تُشتق **فئة خاصة** من استنتاج الذكاء الاصطناعي دون موافقة وأساس مناسب.

## 8. الإقامة ونقل البيانات عبر الحدود
- **`home_region`** لكل عائلة تُحدَّد عند التسجيل بحسب الدولة، وتُخزَّن بياناتها الأساسية في هذه المنطقة (D-022 بعد O-001).
- النقل خارج المنطقة (مزودو الذكاء الاصطناعي مثلًا) يتطلب آلية قانونية (قرارات كفاية، بنود تعاقدية قياسية، موافقة) وتسجيلًا في `processing_registry`.
- إن اشترط قانون دولة إقامة محلية، تُفعَّل منطقة مخصصة قبل إطلاقها.
- الدعم الفني والتحليلات لا تنقل P0/P1 عبر الحدود.
- **عملية تقييم أثر النقل (TIA)** لكل مزوّد ونقل جديد.

## 9. التقييمات والسجلات والمسؤولون
- **DPIA** إلزامي قبل: رقابة المحتوى، الذكاء للأطفال، سجل الموقع، أي فئة خاصة، وأي معالجة واسعة. يُحدَّث عند تغيير جوهري.
- **سجل أنشطة المعالجة (RoPA)** مصدره `processing_registry`.
- **DPO:** يُعيَّن حيث يلزم أو بشكل استباقي عند الإطلاق.
- **ممثل محلي** (حيث يشترط القانون): قائمة الدول في `CountryLegalProfile`.
- **لجنة مراجعة الامتثال** ربع سنوية، ومخرجاتها تُسجَّل.

## 10. حقوق أصحاب البيانات (التشغيل)
- قناة طلبات واحدة داخل التطبيق (مركز الخصوصية) + بريد/نموذج ويب، والتحقق بـ step-up.
- مهلة الاستجابة من `dsr_response_days` (القيمة الافتراضية الأشد إن غابت)، ولوحة SLA داخلية.
- أنواع: وصول وتصدير، حذف، تصحيح، اعتراض/تقييد، سحب موافقة، قابلية النقل، اعتراض على القرار الآلي.
- **حالات خاصة:** طلب مراهق/والد متعارض (security-and-privacy §11)، طلبات من أطراف ثالثة (مرفوضة دون تحقق)، وطلبات الورثة (سياسة حساب الوفاة، تُحدَّد في S1-02 (الحساب) وS1-03 (العائلة)).
- كل طلب مُدقَّق، ونتيجته تُسجَّل (قبول/رفض بالسبب).

## 11. الإبلاغ عن الخروقات
- نقطة قرار قانونية خلال ساعات من الاكتشاف، والمهلة من `breach_notice_hours` (الأساس 72 ساعة حيث ينطبق GDPR).
- قالب إشعار للجهات وللمتأثرين، ومسؤول اتصال، وسجل الخروقات (حتى غير المبلغ عنها).
- يتكامل مع دليل الحوادث (environments-and-devops §10).

## 12. متاجر التطبيقات والمنصات
| المتطلب | الإجراء |
|---|---|
| Google Play: سياسة **Families** و**Device and Network Abuse/Stalkerware** و**Accessibility API** | إفصاح بارز على الجهاز، إشعار دائم ظاهر، لا إخفاء، نموذج تصريح الاستخدام، حدود الاستعمال |
| Google Play: **Data Safety** | تعبئة دقيقة تُولَّد من `processing_registry` |
| Apple: **Family Controls / Screen Time API** | الحصول على الاستحقاق (entitlement) وفق موافقة Apple، وإظهار حدود iOS بصدق |
| Apple: **Privacy Nutrition Labels** و**App Tracking Transparency** | تُولَّد من السجل، ولا تتبع إعلاني أصلًا |
| قواعد فئة الأطفال | قرار مبكر: هل التطبيق في فئة الأطفال أم العائلات؟ يؤثر على الإعلانات ومكتبات الطرف الثالث (لا SDK إعلانية ولا تحليلات غير مقيّدة) |
| الاشتراكات داخل التطبيق | الالتزام بنظام الدفع في المتجر حيث يلزم وبقواعد التجديد التلقائي |
- **القرار T-004 (مفتوح):** التصنيف في المتاجر (عائلات/أطفال/عام) يُحسم قبل بناء S1-01، لأنه يقيّد المكتبات.
- إجراء مراجعة المتجر: صفحة شرح للمراجعين، وحسابات تجريبية، وفيديو شرح التصاريح الحساسة.

## 13. الاشتراكات وحماية المستهلك
- شفافية السعر والتجديد والإلغاء بسهولة مساوية للاشتراك، وإشعار قبل التجديد حيث يشترط القانون.
- ضرائب محلية (VAT/GST/Sales) وفوترة مطابقة، ويُحسم مع monetization-and-plans.
- سياسة استرداد ومنع الحجب القسري للميزات الأمنية الحرجة (SOS يبقى متاحًا في كل الخطط، وهو حد منتج وليس تسعير).
- لا أنماط خادعة (Dark Patterns) في الاشتراك أو الموافقات، وتُفحص في مراجعة التصميم.

## 14. الذكاء الاصطناعي والامتثال
- **تصنيف المخاطر:** ميزات الذكاء للأطفال (رقابة المحتوى، المساعد التعليمي، تحليل المشاعر إن وُجد) تُراجع وفق أنظمة الذكاء المحلية (مثل قانون الذكاء الاصطناعي الأوروبي) قبل التفعيل في الدولة.
- **منع:** لا استدلال عاطفي/بيومتري على الأطفال، ولا تصنيف اجتماعي، ولا قرارات آلية ذات أثر قانوني دون تدخل بشري.
- **الشفافية:** الإفصاح عن التفاعل مع نظام ذكاء، وتسمية المحتوى المولَّد.
- **الاعتراض:** حق طلب مراجعة بشرية لأي استنتاج رقابي يؤثر على الطفل (التنبيه ليس إدانة).
- سجل نماذج ومزودين (Model Register) يربط كل ميزة بنموذج وغرض وتقييم أثر.

## 15. السلامة وإلزامات الإبلاغ (Trust & Safety Legal)
- **مواد الاعتداء على الأطفال (CSAM):** إجراء قانوني-تقني بالتشاور مع مستشار، يحدد الواجب في كل دولة للإبلاغ والمحافظة على الأدلة وعدم تداول المادة، مع سلسلة تصعيد ومدرَّبين. لا يُصمَّم هذا المسار ارتجالًا.
- **تهديدات وشيكة** (إيذاء النفس، خطر على حياة): مسار تنبيه للأهل وخطوط المساعدة المحلية، وسياسة واضحة للتصعيد للجهات حيث يوجب القانون.
- **الإساءة بين المستخدمين:** إبلاغ، إجراءات إنفاذ، تعليق، استئناف.
- الشفافية: تقرير شفافية سنوي لاحقًا.

## 16. طلبات الجهات الرسمية
- **قناة واحدة** مخصصة وإجراء موثق: التحقق من صحة الطلب والاختصاص، ومراجعة قانونية، والحد الأدنى من البيانات، وإشعار المستخدم حيث يسمح القانون، وسجل مفصل.
- طلبات الطوارئ إجراء مستقل عالي السرعة بمعايير صارمة.
- لا وصول مفتوح للمحتوى، وفي نمط `managed` تُحدَّد الإمكانية القانونية بحسب كل دولة بعد مراجعة المستشار.
- تقرير سنوي بعدد الطلبات والاستجابات حيث يُسمح.

## 17. المحتوى وحقوق الملكية
- **المحتوى الديني والتعليمي:** تراخيص واضحة للنصوص والتسجيلات والترجمات (قرآن، حديث، أدعية، مناهج...)، والتحقق من الاعتماد الشرعي/الأكاديمي للمصادر (نظام الوحدات القابل للتوسع، D-016 المنتجات).
- **محتوى المستخدم:** ترخيص تشغيل محدود (استضافة وعرض)، لا ملكية للمنصة، ولا استخدام تسويقي أو تدريبي.
- **الإبلاغ عن انتهاك الحقوق:** إجراء إشعار وإزالة.
- العلامة والشعار: تسجيل الملكية في دول الإطلاق.

## 18. الإعلانات والتسويق
- **لا إعلانات** داخل المنصة ولا بيع ولا مشاركة بيانات للإعلان (أرضية تسويقية).
- التسويق للبالغين فقط وبموافقة، ولا يُراسَل الأطفال.
- إشعارات المنتج للأطفال تقتصر على الوظيفي والتعليمي.

## 19. الحوكمة الدورية
| النشاط | التكرار |
|---|---|
| مراجعة `CountryLegalProfile` النشطة | نصف سنوي أو عند تغيير قانوني |
| مراجعة قائمة المعالجين الفرعيين | ربع سنوي |
| تحديث DPIA | عند كل تغيير جوهري وسنويًا |
| تدريب الفريق (خصوصية، أطفال) | سنوي + عند الانضمام |
| تدقيق داخلي للامتثال | سنوي، وSOC 2 لاحقًا |
| اختبار مسار الحقوق (DSR) والخروقات | نصف سنوي |

## 20. معايير القبول
1. لا تُفعَّل دولة (`status = active`) دون اكتمال حزمة الإطلاق §3.3 وموافقة قانونية مسجلة.
2. كل معالجة جديدة تتطلب مدخلًا في `processing_registry` بأساس وغرض واحتفاظ، وفشل CI عند غيابه.
3. تغيير `digital_consent_age` أو `parental_consent_methods` لدولة يغيّر سلوك التسجيل دون إصدار جديد.
4. إنشاء حساب طفل يفشل برمجيًا دون موافقة والدية نافذة بالنسخة الحالية من الإشعار.
5. تغيير جوهري في وثيقة يستدعي إشعارًا وإعادة موافقة لمن تأثروا، وتُسجَّل النسخة.
6. صفحة Data Safety وملصقات خصوصية Apple تُولَّد من `processing_registry` دون تعديل يدوي.
7. نقل أي بيانات P0/P1 خارج `home_region` مستحيل دون آلية مسجلة (اختبار).
8. طلب حذف/تصدير يُنجَز ضمن `dsr_response_days` المعرّفة لدولة صاحبه، ويظهر في لوحة SLA.
9. دولة بلا ملف تطبيق تفعل القيم الأشد افتراضيًا.
10. SOS متاح في كل الخطط والدول.
11. يوجد دليل مكتوب ومجرَّب بالمحاكاة لـ: خرق بيانات، طلب جهة رسمية، بلاغ سلامة طفل.

## 21. مسائل مفتوحة
- **O-001:** الدول المستهدفة أولًا (يحسم المستوى A وكل ما سبق).
- **T-004:** تصنيف التطبيق في المتاجر (عائلات/أطفال/عام).
- **L-001:** تعيين مستشار قانوني (دولي + محلي لكل دولة إطلاق) لاعتماد `CountryLegalProfile` والوثائق.
- **L-002:** كيان قانوني ومالك حسابات المتاجر (يتصل بـ environments-and-devops §6.2).
