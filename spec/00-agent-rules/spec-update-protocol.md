# بروتوكول تحديث المواصفات

## 1. استقبال المحتوى
يصل المحتوى بكتل تبدأ بسطر === FILE: المسار === وتنتهي بسطر === END FILE ===. ضع ما بينهما حرفيًا في الملف المذكور بدلًا من محتواه كاملًا، دون تعديل أو اختصار أو إعادة صياغة، وأنشئ المجلدات الناقصة.

## 2. بعد كل وضع
1. اترك الترويسة كما وردت، وإن غابت فأضف الترويسة القياسية مع status: drafted.
2. حدّث last_updated في الترويسة بتاريخ اليوم.
3. حدّث الصف المقابل في spec/STATUS.md.
4. أضف سطرًا في spec/99-decisions/changelog.md: التاريخ، المسار، وصف موجز (إنشاء أو تعديل).

## 3. تغيير ملف بعد تنفيذه
إن وصل تعديل لملف حالته implemented أو verified فأعد حالته إلى approved، وأضف في changelog.md قسم «يلزم إعادة العمل» يذكر النظام والملفات المتأثرة، ولا تعدّل الكود قبل أن يأمرك صاحب المشروع.

## 4. التعارضات والنقص
لا تحلها بنفسك: سجّلها في spec/99-decisions/open-questions.md بالصيغة: التاريخ، الملف، وصف المشكلة، الخيار المؤقت، السبب. ثم أخبر صاحب المشروع في ردك.

## 5. التحقق بعد الاستقبال
بعد كل دفعة اطبع: عدد الملفات التي وُضعت، وأي ملف مذكور في الكتل لم يكن موجودًا فأُنشئ.
