# ضبط التغيير — كيف تتغير المواصفة ومن يعتمد

> **الحالة:** معتمد · **التاريخ:** 2026-11-04
> مستخلص من `spec-update-protocol.md` (الفرع السابق) بعد التصفية.

## 1. المبدأ

المواصفة المعتمدة (`approved` فما فوق) لا تُغيَّر بصمت. كل تغيير يمر بهذا المسار.

## 2. المسار

1. **الطلب:** يُسجَّل في `OPEN-QUESTIONS.md` (قالب `templates/open-question.md`): ماذا يتغير ولماذا.
2. **التقييم:** القائد التقني يقدّر الأثر (ملفات/أنظمة/قرارات متأثرة) ويوصي: قبول / رفض / تأجيل.
3. **الاعتماد:** مالك المشروع وحده يعتمد. التوصية لا تُنفَّذ قبل الاعتماد.
4. **التنفيذ:** يُحدَّث الملف + `last_updated` + سطر في سجل القرارات إن كان التغيير قراراً.
5. **إعادة العمل:** إن كان الملف `implemented` أو `verified`، تُعاد حالته إلى `approved`، ويُسجَّل قسم "يلزم إعادة العمل" يذكر الأنظمة والملفات المتأثرة — ولا يُعاد الكود قبل أمر المالك.

## 3. ما لا يحتاج اعتماداً

- تصحيح إملائي/تنسيقي لا يغيّر المعنى.
- تحديث `last_updated` وترويسات الحالة ضمن المسار المعتمد.

## 4. التعارضات

أي تعارض يُكتشف أثناء التغيير: يُبلَّغ عنه فوراً، يُسجَّل في `OPEN-QUESTIONS.md`، **ولا يُحسم بصمت** — يُرفع للمالك مع توصية.
