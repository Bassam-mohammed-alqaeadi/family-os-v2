## 1. تصنيف الحالات

> **مرجع اللون والحالة:** Warning = amber، Danger/SOS = red، Success = green، Info = blue. يجب أن ترافق كل حالة تسمية نصية وأيقونة؛ لا يستخدم اللون وحده. لا تُعرض حالة «مشفّر» أو «متصل» أو «محمي» إلا إذا أكدتها طبقة النظام المعنية.
| الصنف | الحالات |
|---|---|
| **المحتوى** | جديد/فارغ لأول مرة، فارغ بعد تصفية، فارغ بعد حذف، ممتلئ، جزئي |
| **التحميل** | أولي، تحديث، تحميل المزيد، عملية جارية، مزامنة |
| **النجاح** | تم، تم مع تحذير، بانتظار قرار |
| **الخطأ** | شبكة، خادم، تحقق، صلاحية، تعارض، حد، قانوني، جهاز |
| **التوفر الصادق (S1-09 §3/§6)** | السبع حالات (§5) |
| **النظام** | دون اتصال، بيانات قديمة، تحديث إلزامي، صيانة |

## 2. الحالات الفارغة (Empty States)
### 2.1 البنية
أيقونة/رسم مناسب للسياق + عنوان قصير + جملة تشرح + **إجراء واحد واضح**، بنبرة الملف (microcopy).
### 2.2 الأنواع
| النوع | مثال | الإجراء |
|---|---|---|
| **أول استخدام** | «لم تضف أحدًا من العائلة بعد» | «أضف فردًا» |
| **بلا نتائج بحث/تصفية** | «لا نتائج لـ…» | تعديل البحث/مسح المرشحات |
| **لا شيء يحتاج انتباهك** | «كل شيء على ما يرام» (إيجابي) | لا إجراء، أو اقتراح |
| **قريب الاستخدام** | «ستظهر الأماكن هنا بعد إضافتها» | «أضف مكانًا» |
| **غير متاح بحكم الصلاحية/الخطة** | انظر §5 | بحسب الحالة |
| **بعد الحذف/الإنجاز** | «أنهيت كل المهام!» | احتفال خفيف للأطفال |
- الفارغ لا يُعرض كخطأ، وللأطفال رسوم ودودة، وللكبار هادئة ومختصرة.
- **أول تشغيل للعائلة:** قائمة إعداد (Checklist) في مركز القيادة بدل شاشات فارغة متفرقة.

## 3. التحميل
- **أولي:** Skeleton بشكل المحتوى (لا دوّار فارغ)، ويُعرض من **الكاش المحلي فورًا** (offline-first) ثم يُحدَّث.
- **تحديث (Pull to refresh):** مؤشر خفيف، والمحتوى القديم يبقى ظاهرًا.
- **المزيد:** مؤشر أسفل القائمة، وتحميل مسبق عند الاقتراب.
- **عملية جارية:** مؤشر في الزر/السطر، ومنع التكرار.
- **التدرج الزمني:** كما في motion §6.1 (≤100ms رد لمسي فوري، 100–300ms بلا مؤشر إضافي، 300ms–2s هيكل/مؤشر في مكانه، >2s مؤشر + نص توضيحي وزر إلغاء حيث يمكن، >10s رسالة صادقة بإمكانية إعادة المحاولة).
- **المزامنة:** شريط/أيقونة صغيرة بحالة «يتم الحفظ/تم/خطأ مزامنة» لا تحجب العمل.
- لا Skeleton لمحتوى حساس بلا صلاحية (لا يُكشف وجوده).

## 4. الأخطاء
### 4.1 نمط الرسالة
**ما حدث** (بلا لوم، بلغة بشرية) + **لماذا** (إن أفاد) + **ما يمكن فعله** (إجراء واحد أو اثنان). لا أكواد تقنية ظاهرة (يُعرض «رمز المرجع» صغيرًا للدعم).
### 4.2 الأخطاء ← واجهة
| رمز API (ARCHITECTURE.md §5.4: صيغة خطأ موحدة — رمز + رسالة عربية + مرجع تتبع؛ ورموز كل نظام في §4-4 من مواصفته، ومنها S1-09 SPEC §4-4) | الصنف | السلوك |
|---|---|---|
| **شبكة/مهلة** | اتصال | «لا اتصال» + إعادة محاولة تلقائية + حفظ المسودة، والقراءة من الكاش |
| `VALIDATION_FAILED` | تحقق | خطأ مضمَّن بجانب الحقل، لا نافذة |
| `PERMISSION_DENIED` | صلاحية | حالة `not_delegated` (§5) لا «خطأ» |
| `LOCKED` | قفل | شارة قفل وسبب ومن يفكّه |
| `PLAN_LIMIT` | حد خطة | `requires_upgrade` (مالك: «عرض الخطط»، غيره: «اطلب من الأب») |
| `LEGAL_BOUND` | حدّ قانوني | شرح مختصر («لا يمكن بحسب القانون في بلدك»)، لا ترقية |
| `VERSION_CONFLICT` | تعارض كتابة | عرض **الفرق** وخيارات: استخدم قيمتي / قيمته / ادمج (بلا فقدان صامت) |
| `UNAVAILABLE_ON_DEVICE` | جهاز | `unavailable_on_device` + بديل إن وُجد |
| `APPROVAL_REQUIRED` | موافقة | يُنشَأ الطلب، وحالة `pending_approval` |
| 5xx/غير متوقع | خادم | «حدث خلل من جانبنا» + إعادة محاولة + رمز مرجع، وتقرير آلي |
| 429 | معدل | «انتظر قليلًا» مع عدّاد |

[ملاحظة مؤرخة 2026-11-08 (Q-347): كان صف `PLAN_LIMIT` في هذا الجدول يقول «(مالك: ترقية، ...)»؛ صُحح إلى «عرض الخطط» ليوافق جدول §5.]

### 4.3 مستويات العرض
| الحالة | الشكل |
|---|---|
| حقل | نص بجانب الحقل + أيقونة |
| عملية فاشلة | Snackbar مع إعادة محاولة |
| قسم لم يُحمَّل | بطاقة خطأ داخل الشاشة مع إعادة محاولة (باقي الشاشة يعمل) |
| شاشة كاملة فاشلة | حالة كاملة مع إجراء |
| حرج (SOS، حماية فقدت) | بانر ثابت وإشعار، لا يُغلق بالخطأ |
- **الفشل الجزئي:** شاشة تتحمل فشل أحد مكوّناتها (الخريطة لا تعمل لكن القائمة تعمل) دون انهيار.

## 5. الحالات الصادقة (S1-09 §3/§6): الأنماط الموحدة
| الحالة | الأيقونة (`status.*`) | الرسالة النمطية | الإجراء |
|---|---|---|---|
| `available` | — | — | — |
| `unavailable_on_device` | أيقونة جهاز مشطوب | «لا يتوفر على جهاز [الاسم] ([iPhone/نظام])» | شرح البديل/الدعم |
| `pending_approval` | ساعة/انتظار | «ننتظر موافقة [الاسم]» | عرض الطلب/إلغاؤه |
| `not_delegated` | قفل شخص | «لم يُفوَّض لك هذا» | «اطلب من [الأب]» |
| `disabled_by_owner` | قفل | «عطّله [الاسم]» | شرح فقط |
| `requires_upgrade` | نجمة/ترقية | «ضمن خطة [الاسم]» | مالك: «عرض الخطط»، غيره: «اطلب من الأب» |
| `coming_soon` | ساعة/نجمة | «قادم قريبًا» | (تاريخ إن وُجد) |
- تُعرض **داخل الصف نفسه** (FosAvailabilityBadge) وفي شاشة كاملة عند الدخول المباشر (رابط عميق).
- **قاعدة:** لا عنصر يظهر فعّالًا وهو غير منفّذ، ولا زر ميّت بلا شرح.

## 6. حالات النظام
| الحالة | السلوك |
|---|---|
| **دون اتصال** | بانر هادئ، القراءة من الكاش، الكتابات تتجمع (outbox) بشارة «ستُرسل عند الاتصال»، وتعطيل ما يحتاج الخادم بشرح |
| **بيانات قديمة** | «آخر تحديث قبل ٥ دقائق» مع زر تحديث (ضروري للموقع/السلامة) |
| **تحديث إلزامي** | شاشة صادقة بزر المتجر، ولا إغلاق مفاجئ (Q-069: تحديث إجباري داخل التطبيق للإصدارات الأمنية الحرجة فقط + حد أدنى لإصدار مدعوم — S1-01 SPEC REQ-020) |
| **صيانة/توقف** | رسالة بالصفحة وحالة الخدمة، ومسار SOS يبقى |
| **صلاحية نظام ناقصة** | معالج صلاحيات (components §5.4) |
| **جهاز بلا خدمات Google/قيود شركة** | إرشاد لإعدادات البطارية بصدق (Q-022: MQTT-over-TLS قناة أساسية لوكيل الطفل، وFCM/HMS للوحة الأهل فقط — ARCHITECTURE.md §4؛ وS1-01 SPEC REQ-013: مراقب صحة المنصة يرصد البطارية) |
- الموقع: عرض **عمر آخر موقع** ودقته دائمًا، ولا يُعرض قديم كأنه حي.

## 7. حالات النجاح والانتظار
- **نجاح:** تغيير ظاهر + Snackbar قصير (+ تراجع) بدل حوار.
- **بانتظار:** حالة ثابتة قابلة للتتبع (قرار الأب)، وتتحول بحركة وإشعار.
- **تحذير:** (نجح جزئيًا) يسرد ما لم يتم وأسبابه (مثل: تطبيق قالب بتجاوز أقفال).

## 8. حسب الدور وقالب العرض
| الدور (role) | الأسلوب |
|---|---|
| owner | مختصر دقيق، تفاصيل وأسباب، رموز مرجعية، وإجراءات تقنية فورية |
| adult | واضح وبسيط وهادئ |
| teen | مباشر وودّي ومحترم، بلا وصاية |
| child | قصير ومرح ومصوّر، مع زر «اطلب من بابا» (ورسم + صوت في قالب minimal دون 7 سنوات) |
- الأخطاء الحرجة للأطفال تُرسل للأب أيضًا (إشعار) كي لا يُترك الطفل.

## 9. الرسوم والتصميم
- رسوم الحالات الفارغة والخطأ من مجموعة العلامة (brand §7)، متنوعة، بألوان الباليت، وخفيفة الحجم.
- الألوان الدلالية (color-tokens §6) مع أيقونة ونص (لا لون فقط).
- مكوّنات: `FosEmptyState`, `FosErrorState`, `FosInlineError`, `FosStatusBanner`, `FosSkeleton`، كلها في الكتالوج.

## 10. الأمان والخصوصية
- رسائل الخطأ لا تكشف وجود كيان لا حق للمستخدم برؤيته (ولا فرق في الرسالة بين غير موجود وغير مسموح عند الحساسية).
- لا بيانات شخصية في رموز المرجع أو التقارير.
- المسودات والمحتوى المعلّق يُخزَّن مشفّرًا محليًا (ARCHITECTURE.md §8: الحقول الحساسة مشفرة، وTLS في كل اتصال؛ وS1-08 SPEC REQ-010: Envelope Encryption — Q-081).

## 11. معايير القبول
1. DS-ST-01: كل شاشة رئيسية لها حالات (أولي، فارغ، خطأ، دون اتصال، جزئي) موثقة ومختبرة بـ golden.
2. DS-ST-02: كل رمز خطأ API يُترجَم لنمط واجهة وفق §4.2 (اختبار تغطية على رموز الأخطاء).
3. DS-ST-03: الحالات الصادقة السبع موحدة بصريًا ونصيًا في كل مكان تظهر فيه (اختبار).
4. DS-ST-04: `VERSION_CONFLICT` يعرض الفرق ولا يفقد كتابة صامتًا.
5. DS-ST-05: دون اتصال: القراءة تعمل، والكتابات تتجمع وتُسوّى، والبيانات القديمة تحمل عمرها.
6. DS-ST-06: فشل مكوّن واحد لا يعطّل بقية الشاشة (اختبار حقن أعطال).
7. DS-ST-07: لا حالة فارغة بلا إجراء مناسب (أو شرح عند غياب الإجراء).
8. DS-ST-08: رسائل الخطأ لا تحوي رموزًا تقنية ظاهرة ولا لومًا (مراجعة microcopy).
9. DS-ST-09: عرض عمر ودقة الموقع إلزامي على كل عرض موقع.
10. DS-ST-10: أخطاء الأطفال الحرجة تُنشئ إشعارًا للأب.
11. DS-ST-11: وضع النطاق المنخفض يعرض شارة واضحة، ومزامنة يدوية/مجدولة، وبلا تحديثات تلقائية، ومحتوى غير محمّل بحالة «بانتظار المزامنة» (Q-064).
12. DS-ST-13: وضع النطاق المنخفض يتفعّل تلقائياً عند ضعف الاتصال أو يدوياً من الإعدادات؛ وجدولة المزامنة ثلاثة خيارات فقط (كل ساعة / يومياً / يدوي فقط) مع زر «مزامنة الآن»؛ ولا تحديثات تلقائية في هذا الوضع — التحديثات بموافقة صريحة وعلى Wi-Fi فقط؛ وأي محتوى لم يُحمَّل بعد يُعرض بحالة «بانتظار المزامنة» مع زر تحديث، ولا يُعرض قديم كأنه حي (Q-064).

## 12. مسائل مفتوحة
- **ST-001:** مجموعة رسوم الحالات (إنتاج مخصص أم مفتوحة المصدر، B-002).
### قرار محسوم
- **ST-002 (Q-388):** رمز مرجعي عشوائي/معتم بلا بيانات شخصية؛ التفاصيل الداخلية لا تظهر إلا للدعم المخوّل، ولا تعرض الواجهة stack trace أو السجلات الخام.

## 13. وضع النطاق المنخفض (Q-064 — إلزامي في المرحلة 1)

- **التفعيل:** تلقائي عند ضعف الاتصال أو يدوي من الإعدادات؛ ويُظهر شارة «وضع منخفض» في الغلاف.
- **المزامنة اليدوية/المجدولة:** زر «مزامنة الآن» واضح في الشاشات الرئيسية؛ وجدولة مزامنة (كل ساعة/يوميًا/يدوي فقط) في الإعدادات؛ ولا مزامنة تلقائية في الخلفية.
- **بلا تحديثات تلقائية:** لا تحميل أصول أو تحديثات تطبيق تلقائيًا في هذا الوضع؛ والتحديثات بموافقة صريحة وعلى Wi-Fi فقط.
- **ميزانيات الضغط:** كل استجابة مضغوطة (Brotli/Gzip)؛ وصور مصغرة أولًا (≤ 30KB) مع تحميل كامل بطلب؛ ورسوم ≤ 100KB؛ ولا تحميل مسبق للوسائط.
- **الصدق:** أي محتوى لم يُحمَّل بعد يُعرض بحالة «بانتظار المزامنة» مع زر تحديث، ولا يُعرض قديم كأنه حي.
