## 1. الأهداف
1. **الاطمئنان بنظرة واحدة:** حالة العائلة والأعضاء والأجهزة.
2. **القرار أولًا:** كل ما يحتاج قرارًا (موافقة، تنبيه) في الأعلى وبنقرة.
3. **التحكم من مكانه:** كل خدمة لها لوحة وملخص وإعدادات متاحة من نفس السياق.
4. **تخصيص بحسب الدور:** كل ملف تجربة يرى رئيسية مناسبة (S1-01 §1).
5. **حيّ وموثوق:** تحديث لحظي بصدق عن عمر البيانات.

## 2. بنية مركز القيادة (adult المالك / adult غير المالك)
الفتحات (S1-09 §3) بترتيب ثابت:
1. `header_slot`: التحية والعائلة والإشعارات وSOS.
2. `status_strip`: ملخص حالة العائلة والأجهزة والحماية؛ لا تعرض «الجميع بخير» إلا إذا كانت مصادر الحالة حديثة ومكتملة. أظهر عدد المتصلين ووقت آخر تحديث وأي جهاز غير متصل/بيانات قديمة بوضوح.
3. `hero_slot`: **أهم عنصر الآن** (حدّد بقاعدة الأولوية §3).
4. `quick_actions_slot`: 3-6 إجراءات (رسالة للعائلة، مشاركة موقع، وضع الهدوء، قفل سريع، طلب تسجيل وصول...).
5. `cards_feed`: بطاقات الأعضاء، ثم بطاقات الخدمات المفعّلة بأولويتها.
- **الأحجام:** كل ويدجت s/m/l ويُعاد ترتيبها بحسب العرض (spacing §6).

## 3. قاعدة الأولوية (Attention Queue)
ترتيب ما يظهر في `hero_slot` و«تحتاج انتباهك»، بدرجة أولوية ثابتة مع تعديل زمني:
| الدرجة | العنصر |
|---|---|
| **P0** | SOS نشط، تنبيه خطر طارئ، فقد اتصال طفل ضمن سياق خطر |
| **P1** | تنبيه مخاطر عالٍ، خروج من منطقة آمنة (غير متوقع)، فقد حماية جهاز طفل |
| **P2** | طلبات موافقة (وقت إضافي، تغيير)، استثناءات تنتهي، فشل دفع يهدد الخدمة |
| **P3** | تنبيهات متوسطة، تغيّر في السلوك، بطارية منخفضة لطفل |
| **P4** | ملخصات، إنجازات، اقتراحات النظام |
- P0 **يغطي** `hero_slot` ويبقى حتى الإقرار، ولا يمكن إخفاؤه.
- العناصر المتكررة تُجمَّع، وتزيد الأولوية مع تصاعد الشدة لا التكرار.
- العنصر الذي عولج يختفي من كل الأجهزة (إبطال).
- **حد الظهور:** ≤ 7 بطاقات قبل التمرير للبالغين، ≤ 4 للأطفال.

## 4. الويدجتات (Widget Contract)
```
WidgetRegistration {
  id, service_id, title_key, size[s|m|l], priority_fn,
  supported_profiles[], required_permission, scope (family|member),
  data_source (API + realtime topic), freshness_ttl,
  states { loading, empty, error, unavailable }, // حالات الويدجت الأربع — ليست الحالات الصادقة السبع (S1-09 §3/§6)
  actions[] { key, label_key, deep_link, required_permission },
  privacy { lockscreen_safe: bool, contains_sensitive: bool }
}
```

- الأنظمة اللاحقة تضيف ويدجتاتها بالتسجيل (شاشة الرئيسية تظهر بلا تعديل نواة).

## 5. لوحات الخدمات (Service Dashboards)
لكل خدمة **لوحة** بنمط موحد، تفتح من بطاقتها أو من «الخدمات»:
1. **الرأس:** اسم الخدمة، **حالتها الصادقة** (فعّالة/غير مفعّلة/ناقصة صلاحية/ترقية)، زر الإعدادات.
2. **ملخص** (3-4 مؤشرات رئيسية بلغة بسيطة، مثل «٤٥ د شاشة اليوم، الحد ٢ س»).
3. **بحسب العضو:** مبدّل الأعضاء (شرائح أو قائمة) يعرض وضع كل فرد، وإجراء/استثناء سريع.
4. **النشاط الأخير:** خط زمني لأحداث الخدمة مع تصفية.
5. **تحكمات سريعة:** 3-5 تحكمات مفتاحية من قالب الخدمة (من `FosSettingRow`)، و«كل الإعدادات» تفتح صفحة الخدمة في مركز الإعدادات (settings-patterns).
6. **توصيات:** (اختياري) اقتراحات بقيم مقترحة تُعرض ولا تُطبَّق آليًا لتحكمات الحماية.
- الرسوم: خطّية/أعمدة/حلقية بالباليت، وتسمية مباشرة، وبدائل جدولية، وفترة (اليوم/الأسبوع/الشهر) بحسب الاحتفاظ والخطة.

## 6. رئيسية بقية الملفات
| الملف | التركيب |
|---|---|
| **adult (مفوّض)** | نفس البنية ضمن نطاق التفويض (أفراد/خدمات محددة)، وما ليس لهم لا يظهر أو يُعرض بحالة صادقة |
| **adult** | حالة العائلة، الموقع المشارك، محادثات، مهام، إعدادات شخصية |
| **teen** | مهام، أهداف، رسائل، محتوى تعلّم، «ماذا تراقب عائلتي؟» (child-mode-ui) |
| **child** | مرشد، مهام اليوم، مكافآتي، اطلب من بابا |
| **child (قالب minimal)** | بلاطات كبيرة (child-mode-ui §3.1) |
- كلها من **نفس مولّد الويدجتات** بتكوين ملف التجربة.

## 7. التخصيص
- **للأب/الكبار:** ترتيب الويدجتات وإخفاء غير الحرج وتغيير الأحجام ضمن حدود (لا إخفاء لـ SOS والموافقات الحرجة).
- **للأب على رئيسية الأطفال:** يحدد المهام والبلاطات المتاحة ضمن إعدادات الطفل.
- **الحفظ:** تفضيل شخصي للفرد يتبعه على أجهزته.
- **اللوحات الجاهزة:** «يومي»، «سفر»، «موسم الدراسة»، «رمضان»… (قوالب تخطيط) تفعَّل بنقرة.

## 8. البيانات الحية والأداء
- **المصدر:** API + قنوات لحظية (`family:{id}`, `member:{id}`)، وتحديث بالفروق لا إعادة تحميل.
- **الكاش:** يُعرض فورًا من المحلي (offline-first) مع `freshness_ttl`، و«آخر تحديث» ظاهر للحساسة (الموقع).
- **الأحمال:** كل ويدجت يُحمَّل كسولًا، والمرئي أولًا، والخطأ في ويدجت لا يكسر الشاشة.
- **الميزانية:** تفاعل الرئيسية < 1.2s بدء بارد؛ وقراءات لوحة الأهل p95 < 300ms؛ ولا ويدجت يتجاوز ميزانية الإطارات (Q-061 · Q-066).
- **الإبطال:** تغيّر أي طبقة تحكم أو صلاحية يحدّث الويدجتات المتأثرة خلال ثوانٍ.

## 9. الخصوصية والصلاحيات
- **صدق الحالة:** كل بطاقة حالة تعرض المصدر ووقت التحديث عند أهمية الحداثة؛ اللون يتبع `color-tokens.md` (Warning amber، Danger red، Success green، Info blue) ولا يستخدم وحده.
- **عدم إخفاء التدهور:** إذا فقد الجهاز الاتصال أو انتهت صلاحية البيانات، اعرض «آخر تحديث...» أو «بانتظار المزامنة» بدلاً من استمرار عبارة «الجميع بخير».
- كل ويدجت يُفحص بـ `can()` وقت العرض (لا يظهر ما سُحبت صلاحيته).
- **وضع الخصوصية (Privacy Mode):** إخفاء الأسماء/المواقع الدقيقة والتفاصيل الحساسة بنقرة للعرض أمام الآخرين، ويعمل على الشاشة المقفلة بحسب الإعداد.
- لا محتوى رسائل أو صور في الويدجتات (إشارات وأعداد فقط).
- **العرض كـ:** يعرض الرئيسية بصلاحيات الهدف مع شريط معاينة وبلا إجراءات.

## 10. أول استخدام والإعداد
- مركز القيادة لعائلة جديدة يعرض **قائمة إعداد حية**: أضف أول فرد، أقرن جهاز طفل، فعّل مشاركة الموقع، اختر قالبًا، عيّن جهات طوارئ (SOS)، ادعُ الشريك. كل بند يفتح معالجه ويُشطَب عند الإنجاز.
- نسبة اكتمال الإعداد تُقاس من إنجاز بنود القائمة (Q-046 مفتوح — سياسة التحليلات لحسابات الأطفال؛ وهدف «أول فرد خلال 24 ساعة» سؤال مفتوح Q-157 (حوكمة، مرحلة التصميم)).

## 11. معايير القبول
1. DS-CC-01: الرئيسية تُركَّب من `WidgetRegistration` والصلاحيات وملف التجربة، وإضافة ويدجت بتسجيله تظهر دون تعديل شيفرة الرئيسية.
2. DS-CC-02: عناصر P0 تتصدر الرئيسية ولا يمكن إخفاؤها، وتختفي من كل الأجهزة عند الإقرار.
3. DS-CC-03: ترتيب الأولويات يطابق الجدول §3 ويثبته اختبار على سيناريوهات مختلطة.
4. DS-CC-04: كل ويدجت له حالات (تحميل، فارغ، خطأ، غير متاح) صادقة، وفشل واحد لا يعطل البقية.
5. DS-CC-05: لوحة كل خدمة بالبنية الموحدة (رأس، ملخص، بحسب العضو، نشاط، تحكمات سريعة، إعدادات) وتتولد من السجلات.
6. DS-CC-06: الويدجتات لا تعرض محتوى رسائل أو صورًا، وPrivacy Mode يخفي الحساس.
7. DS-CC-07: سحب صلاحية يزيل ويدجتها أو يحوّلها لحالة صادقة خلال ثوانٍ.
8. DS-CC-08: الرئيسية تحمّل من الكاش فورًا وتعرض عمر الموقع، وتحقق ميزانية البدء والإطارات.
9. DS-CC-09: «العرض كـ» يعرض رئيسية الهدف دون إجراءات ودون محتوى رسائل.
10. DS-CC-10: قائمة الإعداد الأولي تُحدَّث وتُشطَب تلقائيًا بالإنجاز، وتُقاس.
11. DS-CC-11: ميزانيات الأداء محققة: إقلاع بارد < 1.2s، وقراءات لوحة الأهل p95 < 300ms، وتوصيل أوامر + إقرار < 5s، وتنبيه SOS < 10s (Q-061 · Q-066).

## 12. المسائل المتبقية والقرارات المحسومة
### قرار محسوم
- **CC-001 (Q-393):** لا يوجد مبدّل عائلة في MVP/المرحلة 1؛ كل حساب مرتبط بعائلة واحدة وفق Q-008. لا تعرض تحكماً معطلاً لميزة غير موجودة.
### قرار محسوم
- **CC-002 (Q-391):** ملخص المرحلة 1 حتمي من حالات موثقة ومحدّثة؛ لا يولّد الذكاء أحكاماً عن سلامة العائلة أو حالة الأجهزة. أي صياغة ذكية لاحقة تحتاج تفويضاً وميزانية وتحققاً ولا تستبدل مصدر الحالة.

## 13. ميزانيات الأداء (Q-061)

- **الإقلاع البارد:** < 1.2 ثانية على الأجهزة المتوسطة (يُقاس في مختبر Q-027).
- **قراءات لوحة الأهل:** p95 < 300ms.
- **الإطارات:** ≥ 95% إطارات سلسة على الجهاز المرجعي المتوسط؛ وتنخفض الزخرفة آليًا على الأجهزة المنخفضة.
- **توصيل الأوامر:** تسليم الأمر + إقرار < 5 ثوانٍ عند الاتصال الطبيعي؛ وتنبيه SOS < 10 ثوانٍ.
- **القياس:** تُقاس كل ميزانية في CI على الجهاز المرجعي، والفشل يوقف الإصدار.
