# بوابات الجودة وتعريف الإنجاز

> **الحالة:** معتمد من المالك · **تاريخ الاعتماد:** 2026-11-05
> مستخلص من `definition-of-done.md` (الفرع السابق) بعد التصفية.

## 1. حالات العمل

`drafted` → `approved` (موافقة المالك) → `implemented` (نفّذه الوكيل) → `verified` (اجتاز الفحوص + قبل المالك).
`verified` لا تُمنح ذاتياً أبداً.

## 2. إنجاز الشاشة

- تطابق مواصفة الشاشة عنصراً بعنصر، برموز التصميم فقط (لا ألوان/مقاسات ثابتة في الكود).
- RTL سليم + لغة ثانية دون كسر التخطيط.
- كل الحالات: تحميل، فارغة، خطأ، بلا اتصال، نجاح.
- إمكانية الوصول: لمس ≥48 نقطة، تباين كافٍ، تسميات قارئ الشاشة، تكبير الخط.
- كل النصوص من ملفات الترجمة — لا نص ثابت في الكود.
- الأحداث التحليلية المحددة مرسلة (بلا بيانات شخصية).
- الصلاحيات مطبقة في الواجهة **وفي الخادم**.

## 3. إنجاز المهمة البرمجية

- lint والتنسيق بلا تحذيرات.
- اختبارات وحدة للمنطق الجديد؛ تغطية المنطق الأساسي ≥80%.
- لا TODO/FIXME ولا كود معطّل ولا طباعة تصحيح.

## 4. إنجاز النظام (شرط `verified`)

1. كل معايير القبول مرتبطة باختبار آلي ناجح.
2. اختبارات التكامل وعقود الواجهات ناجحة.
3. ترحيلات قاعدة البيانات تعمل للأمام وللخلف على بيانات تجريبية.
4. فحص الأمان: مدخلات، صلاحيات كل endpoint، لا تسرب للسجلات، فحص الاعتماديات.
5. الأداء ضمن الحدود (إلى أن تُكتب: بدء بارد <2.5ث على جهاز متوسط؛ استجابة القراءة p95 <300ms).
6. التوثيق محدّث + تقرير الإنجاز مكتوب.

## 5. ما لا يُحتسب إنجازاً

شاشة بلا منطق حقيقي · منطق بلا اختبار · ميزة تعمل على الحالة السعيدة فقط · بيانات وهمية في مسار الإنتاج.

## 6. بوابات المراحل

| البوابة | الشرط |
|---|---|
| G1 نهاية التخطيط | الحوكمة كاملة + كل الفئة (أ) محسومة + مراجعة المالك |
| G2 نهاية كل نظام | §4 أعلاه + مراجعة مسجلة |
| G3 نهاية كل مرحلة | كل أنظمتها `verified` + مراجعة سياسات المتاجر + مراجعة أمنية |
| G4 قبل الإطلاق | اختبار ميداني + مراجعة قانونية/شرعية + خطة التراجع |

**بوابة إضافية دائمة:** مراجعة سياسات المتاجر قبل **كل** إصدار (درس Q-026).

## 7. التنفيذ الآلي (Q-170)

- **CI على كل دفع** (`.github/workflows/ci.yml` + `dart.yml`): فحص الوثائق (Mermaid + الروابط + حساب المفاتيح) + بناء الخادم + تحليل واختبار العميل.
- **`verified` تتطلب CI أخضر** على الفرع — لا تُمنح مع CI أحمر.
- **الهيكل الفارغ** (`server/` + `client/`) إثبات بناء فقط — بلا ميزات؛ وتجاوز G-003 بهذا القدر حكم صريح من المالك (Q-170).
