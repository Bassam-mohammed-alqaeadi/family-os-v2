# ملف إرشادات وتوثيق جرد تطبيق Telegram — عائلتي (Family OS)

> **معرّف التطبيق:** `telegram`
> **الحزمة المفحوصة:** `org.telegram.messenger` (v13.1.1, versionCode 72371)
> **البنية المعمارية:** عميل مراسلة أحادي التطبيق — نواة شبكات أصلية (C++) عبر JNI + طبقة Java مُنسِّقة +
> singletons لكل حساب (سقف 4) + حافلة أحداث مركزية (348 حدثاً) + طوابير خيوط مُدارة
> **المرحلة:** سلسلة التوثيق العميق للخطة الموحدة #3 (Unified-Plan deep-doc series #3)
> **الدور الاستراتيجي:** **المرجع المعماري الوحيد لمعيار 10M+ مستخدم متزامن** في Family OS
> **حالة الاعتماد:** مكتمل ومحقق — أول جرد يفكك مسار التحديثات من السوكيت إلى الواجهة 🎯

> **فخر هذا الجرد:** كل الجرود السابقة (بما فيها تقرير الجولة الأولى) اكتفت بعناوين الأنماط
> (`DispatchQueue`، `NotificationCenter`). هذا أول جرد **يتتبع الآلة فعلياً**: نقطة دخول JNI
> (`onUnparsedMessageReceived`) → `stageQueue` → `processUpdates` → الفروق عند الفجوات،
> وبأرقام مُقاسة (32KB/128KB × 4، 348 حدثاً، 2,043 مُنشئ TL، ~80 جدولاً).

## 3. ملخص بوابات الجودة وحدود الإثبات

1. **الأرقام مُقاسة لا مُخترعة:** 22,270 ملف smali و10,362 ملف java (مُقاسة بـ `find`)؛
   348 حدثاً (مُقاسة)؛ 2,043 فئة TL (مُقاسة)؛ ~80 جدولاً (مستخرجة من `CREATE TABLE`)؛
   32KB/128KB/10MB/×4 (مقروءة من smali).
2. **حدود الإثبات الملزمة:** الفئات الأربع الساقطة من jadx (`MessagesController`، `MessagesStorage`،
   `NotificationsController`، `SendMessagesHelper`) حُللت من smali حيث لزم — موسومة Partial لا A.
3. **النواة الأصلية غائبة:** صفر ملفات `.so`؛ الـ 27+ دالة `native_*` تعريفات فقط —
   أي ادعاء عن سلوك النواة الداخلي موسوم [INFERENCE] أو «غير محسوم».
4. **الأمانة العلمية:** كل نتيجة موسومة `[VERIFIED]` (قُرئ الكود/قِيس) أو `[INFERENCE]`
   (مستنتجة)؛ الوثيقة المرافقة `deep-dives/telegram.md` تحمل التفصيل السردي الكامل.

> **ملاحظة:** ملف `sources.json` (18M) يبقى محلياً لتعذر دفعه عبر حد GitHub API (4MB) — قابل لإعادة التوليد حتمياً من الأشجار المحلية عند الحاجة.
