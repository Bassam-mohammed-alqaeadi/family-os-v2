# ملف إرشادات وتوثيق جرد تطبيق Life360 — عائلتي (Family OS)

> **معرّف التطبيق:** `life360`
> **الحزمة المفحوصة:** `com.life360.android.safetymapd` (v26.41.0)
> **البنية المعمارية:** تطبيق سلامة عائلي أحادي — نواة الموقع + كشف الحوادث + الدائرة العائلية
> **المرحلة:** سلسلة التوثيق العميق للخطة الموحدة #3 (Unified-Plan deep-doc series #3)
> **حالة الاعتماد:** مكتمل ومحقق — أعمق جرد لآلة حالة حوادث في البرنامج 🎯

> **فخر هذا الجرد:** تقرير الجولة الأولى سجّل `EventController` و`HeartbeatReceiver` و`MovementDetectionReceiver`
> و`AutomaticCollisionResponseService` و`ProximityGeofenceReceiver` كـ "smali فقط — يحتاج قراءة".
> هذا الجرد **قرأها**: آلة الحالة الثلاثية مفككة انتقالاً بانتقال من الـ smali، وكاشف الحركة اللاجي-بي-إسي
> موثق خوارزمياً، ومصافحة الاصطدام الخادمية مُتتبَّعة سطراً بسطر.

## 3. ملخص بوابات الجودة وحدود الإثبات

1. **آلة الحالة:** الحالات الثلاث (`alert`/`cooling_period`/`survey`) والانتقالات والحد الأقصى (4 محاولات / 5 عروض) مثبتة بقراءة smali كاملة — ليست استنتاجاً.
2. **كشف الحركة:** خوارزمية WiFi-BSSID + الأبراج الخلوية بلا GPS مثبتة بالقراءة (1,219 سطراً) مع الثوابت الزمنية الحرفية.
3. **حدود الإثبات الملزمة:** خوارزمية كشف الاصطدام الفيزيائية داخل SDKs مغلقة (Arity/Sentiance) — لا تُدَّعى؛ مسار REST الاصطدام endpoint ديناميكي (Partial)؛ قيم المهلة الإنتاجية خادمية (Level B).
4. **الأمانة العلمية:** كل نتيجة موسومة `[VERIFIED]` (قُرئ الكود) أو `[INFERENCE]` (مستنتجة)؛ الأعداد مقاسة فعلياً لا مخمنة.

> **ملاحظة:** ملف `sources.json` (17M) يبقى محلياً لتعذر دفعه عبر حد GitHub API (4MB) — قابل لإعادة التوليد حتمياً من الأشجار المحلية عند الحاجة.
